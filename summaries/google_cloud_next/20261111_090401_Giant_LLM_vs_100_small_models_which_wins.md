# Giant LLM vs. 100 small models: which wins?

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=asLjuZlnO4I
- **요약 일시**: 2026-11-11 09:04:01

---

## 🔑 핵심 요약
- "말 크기 **거대 LLM 1개** vs 오리 크기 **소형 언어 모델(SLM) 100개 떼**" 중 어느 쪽으로 앱을 출시할지 묻는 퀴즈쇼 형식의 짧은 영상
- 한 패널은 요즘 거대 LLM은 사실상 모두 내부적으로 **전문가 혼합(`MoE`)** 구조라서 질문 자체가 함정이라고 지적
- 다른 패널은 SLM 떼가 **더 전문화**되어 있고 **라우팅이 빠르며 토큰 소모가 적다**는 이유로 SLM 100개를 선택했고, 1라운드는 MoE를 지적한 앨런 블록이 승리(3점)

---

## 📣 주요 발표 내용
- 신기능·제품 발표는 없는 가벼운 토론/퀴즈 형식의 콘텐츠
- 쟁점 1: 현대 대형 모델은 `Mixture of Experts` 구조라 "거대 모델 1개 vs 작은 모델 여러 개"의 구분이 이미 모호함
- 쟁점 2: 다수의 SLM은 작업별로 **고도로 특화**할 수 있음
- 쟁점 3: SLM 구성은 **라우팅 지연이 짧고** **토큰 비용이 낮다**는 장점이 언급됨

---

## 💡 개발자 포인트
- 모델 아키텍처를 고를 때는 "큰 모델 vs 작은 모델" 이분법보다 **MoE 내부 라우팅**과 **외부 다중 모델 라우팅**의 차이를 따져볼 것
- 작업이 명확히 나뉜다면 특화된 SLM 여러 개 + 라우터 구성이 **지연시간·토큰 비용** 측면에서 유리할 수 있음
- 범용성이 필요한 경우에는 MoE 기반 대형 모델 하나로도 내부적으로 전문가 분할 효과를 얻을 수 있음

> ⚠️ 주의: 원본 자막이 매우 짧고(1라운드 분량) 농담 섞인 대화라 구체적인 벤치마크·수치·제품명은 나오지 않음
