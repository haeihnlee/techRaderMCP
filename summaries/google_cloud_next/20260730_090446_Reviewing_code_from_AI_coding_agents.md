## 🔑 핵심 요약
- **AI 코딩 에이전트는 도구**이며, 결과물에 대한 책임은 전적으로 개발자에게 있다는 관점
- 작업 비중이 **"90% 코딩 / 10% 리뷰"에서 "10% 핸드코딩 / 90% 리뷰"로 역전**됐다는 진단
- 생성한 코드를 전부 커밋할 의무는 없다 — **선별해서 커밋하는 것이 정상**

---

## 📣 주요 발표 내용
- Hacker News 등 개발자 커뮤니티에서 **"손으로 코딩으로 돌아간다"**, **"AI 에이전트는 유지보수 비용을 줄여야 한다"**는 반발 흐름을 화두로 제시
- 이에 대한 답: AI는 붓을 **전동 자동 붓**으로 바꾼 것에 불과하며, 그림의 책임자는 여전히 화가
- 프로젝트 성격에 따라 리뷰 강도를 나눌 것을 권장
  - 일회성 **바이브 코딩**(개인 게임 등) → 코드 검토 생략 가능
  - **프로덕션 코드베이스** → 반드시 검증 절차 필요
- 프로덕션 권장 워크플로: **draft PR 생성 → 수동 또는 AI 리뷰 → 통과분만 병합**
- `Claude Code` 사용 시 **permissions**·**hooks** 를 활용해 리뷰·검증을 자동화하고, 디자인 스펙 준수 여부를 사전에 강제하라는 조언

## 💡 개발자 포인트
- **핸드코딩 시절엔 리뷰의 90%가 "쓰는 도중"에 자연스럽게 일어났다.** 에이전트가 코드를 쓰면 그 자연 리뷰 단계가 사라지므로, 별도의 검증 레이어를 명시적으로 만들어야 한다.

> **마인드셋 전환이 핵심 리스크**: 많은 개발자가 아직 "더 많이 리뷰해야 한다"는 전환을 못 했다. 코드 생산 속도만 올리고 리뷰 체계를 그대로 두면 기술 부채가 그대로 누적된다.

- 10만 줄을 생성했다고 10만 줄을 커밋할 필요는 없다 — **맞다고 판단한 것만 커밋**
- 리뷰를 "귀찮은 일"로 두지 말고 **자기 환경에서 최대한 쉽게** 만들어 둘 것 (`hooks`, 권한 설정, 자동 리뷰 파이프라인)
- 결론: 지금은 **좋은 리뷰어가 되는 역량**이 그 어느 때보다 중요한 시기
