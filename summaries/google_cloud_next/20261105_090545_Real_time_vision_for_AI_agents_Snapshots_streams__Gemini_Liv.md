## 🔑 핵심 요약
- **Gemini Live API** 에이전트는 오디오와 같은 라이브 세션으로 **이미지 블롭(blob)**(바이트 + MIME 타입)을 받아서 시각 정보를 처리함
- 라이브 비디오는 MP4 같은 영상 파일이 아니라 **정지 프레임이 시간 순서대로 이어지는 것**임
- 프레임 전송 방식은 **스냅샷**(한 번 의도적으로 보기)과 **스트림**(계속 지켜보기) 두 가지이고, 기본값은 스냅샷임

---

## 📣 주요 발표 내용
- 한 라이브 세션 안에서 같은 모델이 오디오 청크와 이미지 프레임을 함께 받음
- 프레임 파이프라인은 카메라 → 캔버스 → JPEG → 이미지 블롭 → 모델 순서임
- SDK는 오디오 전용이라는 오해를 정정함: SDK도 같은 Gemini API 위에서 동작하므로 이미지 블롭 경로를 그대로 쓸 수 있음
- **스냅샷**: "이거 봐"처럼 의도한 순간에 이미지 한 장을 보내고, 모델은 이를 다음 대화 턴에 활용함
- **스트림**: 사람이 움직이거나 장면이 바뀌는 상황처럼 계속 인식해야 할 때 프레임을 연속으로 보냄
- 음성과 비전을 함께 쓰면 "이게 뭐야?"의 '이것'이 프레임 속 대상을 가리키게 되어 지시어의 모호함이 사라짐
- 고급 패턴: 대화 모델과 **감시용 비전 모델**을 분리하는 방식. 감시 모델이 위험·제스처·상태 변화를 스캔하고, 메인 에이전트는 모든 프레임을 처리하지 않고 대화를 이어감
- 양방향 라이브 멀티모달 에이전트 시리즈(GenAI SDK → `ADK` → 도구·브라우저 제어·메모리 → 비전)의 마지막 회차임

## 💡 개발자 포인트
- 브라우저에서는 카메라 프레임을 `canvas`에 그린 뒤 JPEG로 변환하고, 백엔드에서 MIME 타입(`image/jpeg`)과 함께 블롭으로 감싸 전송함
- 실용 규칙: 에이전트가 **한 번 보면 되면 스냅샷**, **변화를 지켜봐야 하면 스트림**
- 프레임마다 **컨텍스트와 토큰을 소모함**. 이미지가 너무 많으면 실시간 음성 대화가 끊길 수 있음

> ⚠️ 브라우저 에이전트에서 페이지를 계속 스트리밍하면 실시간 오디오 세션이 중단될 수 있음. 클릭·입력 같은 동작이 끝날 때마다 스크린샷 1장(스냅샷)만 보내는 것으로 충분함

> ⚠️ 음성 세션이 불안정하면 프레임을 너무 많이 보내고 있을 가능성이 큼. 스트림이 필요할 때도 **프레임 속도를 낮게** 유지할 것

- 스냅샷 이미지는 대화 턴을 기다리므로 음성을 방해하지 않음. 스트림은 백그라운드에서 계속 들어오므로 신중하게 써야 함
- 규모가 커지면 비전 감시를 별도 모델로 분리해서 메인 대화 모델의 부하와 토큰 사용을 줄이는 구조를 검토할 것
