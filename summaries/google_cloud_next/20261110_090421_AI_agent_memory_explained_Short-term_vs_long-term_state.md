# AI agent memory explained: Short-term vs. long-term state

> ⚠️ 영상 제목은 "에이전트 메모리(단기/장기 상태)"이지만, 추출된 자막 본문은 **AI 에이전트 평가 방법**을 다룹니다. 아래 요약은 자막 내용을 기준으로 작성했습니다.

## 🔑 핵심 요약
- AI 에이전트를 평가하는 대표적인 방법은 **LLM-as-a-Judge**, **결정론적 평가**, **사용자 지정 함수** 세 가지
- 결정론적 평가(예: ADK의 `trajectory` 평균 점수)는 고정 규칙으로 도구 호출 순서를 골든 데이터셋과 정확히 비교
- 시스템 요구사항에 맞춰 한 가지만 쓰거나 여러 방식을 조합해 에이전트의 안정성과 프로덕션 준비 상태를 검증

---

## 📣 주요 발표 내용
- **LLM-as-a-Judge**: 에이전트 응답, 참조할 사실 관계, 평가 기준을 별도 모델에 넘겨 명확성·정확성·사실 근거 여부를 판단
- LLM 심사 결과는 **점수** 또는 **합격/불합격** 형태로 반환
- **결정론적 평가**: 코드가 고정 규칙을 검사하며, 같은 입력이면 항상 같은 결과를 냄
- ADK 내장 **궤적 평균 점수(trajectory average score)**: 에이전트가 정해진 도구를 **예상 순서대로** 호출했는지 확인
- **사용자 지정 함수**: 도메인에 특화된 검사 로직을 직접 작성(예: 실제 결제 금액보다 더 많이 환불했는지 검사)
- 사용자 지정 함수는 결정론적일 수도 있고, 내부에서 LLM을 감싸면 비결정론적일 수도 있음

---

## 💡 개발자 포인트
- 고객 환불 에이전트 예시: 환불 실행 **전에** 주문 내역 조회 도구를 호출했는지 `trajectory` 평가로 검증할 수 있음
- 궤적 평가는 **정확 일치(exact match)** 비교이므로 골든 데이터셋의 도구 호출 순서를 신중하게 설계해야 함
- 결정론적 평가만으로는 유연성이 부족하므로, 비즈니스 규칙(금액 한도 등)은 사용자 지정 함수로 보완
- 응답 품질(명확성·사실성)처럼 규칙으로 표현하기 어려운 항목은 LLM-as-a-Judge로 평가

> 사용자 지정 함수 안에 LLM을 넣으면 결과가 **비결정론적**이 되어 재현성이 떨어질 수 있습니다. CI 회귀 테스트에 쓸 검사는 결정론적으로 유지하는 것을 권장합니다.

| 평가 방식 | 결정론 여부 | 적합한 용도 |
|---|---|---|
| LLM-as-a-Judge | 비결정론적 | 응답 품질, 사실 근거 여부 |
| 결정론적 평가 (`trajectory`) | 결정론적 | 도구 호출 순서·정확성 |
| 사용자 지정 함수 | 둘 다 가능 | 도메인 비즈니스 규칙 검사 |
