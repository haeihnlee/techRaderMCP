# Stop building voice AI like an API call

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=k9Sv9mkyjcQ
- **요약 일시**: 2026-09-15 09:06:55

---

## 🔑 핵심 요약
- **라이브 AI 에이전트**는 일반 API 호출 방식으로 구현하면 안 됨 — 지속 실행되는 시스템이기 때문
- **ADK(Agent Development Kit)** 의 `live request queue`를 사용하면 오디오 입출력을 동시에 처리 가능
- 에이전트는 한 번 호출하는 게 아니라 **실시간 루프 시스템**으로 설계해야 함

---

## 📣 주요 발표 내용
- 일반 API 호출 패턴 (요청 → 대기 → 응답) 은 라이브 에이전트에 부적합
- `ADK live request queue` 는 컨베이어 벨트처럼 동작: 앱은 계속 오디오 청크를 추가, 라이브 세션은 이를 계속 소비
- 오디오 입력 루프와 모델 오디오 출력 수신 루프가 **동시에 병렬 실행**
- 이벤트 종류: 음성(Voice), 자막(Captions), 도구 호출(Tool calls), 인터럽션(Interruptions)

---

## 💡 개발자 포인트
> 라이브 에이전트를 단순 API 호출로 구현하면 지속적인 문제가 발생함 — 라이브 세션은 절대 완전히 종료되지 않는 실행 시스템이므로 비동기/스트리밍 설계 필수

- `ADK`의 `live request queue` 패턴을 사용해 오디오 스트리밍 처리
- 에이전트와의 상호작용은 **단일 요청/응답이 아닌 지속 실행 루프** 기반으로 설계
- 구체적인 구현은 **시리즈 4번째 영상**에서 상세 설명 예정
