# Computer use vs. WebMCP: How AI agents use the web

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=8p2EmLiQL9c
- **요약 일시**: 2026-11-14 09:05:03

---

## 🔑 핵심 요약
- AI 에이전트가 웹을 쓰는 두 가지 방식 비교: 사람처럼 화면을 보고 마우스를 움직이는 **Computer use** vs. API를 직접 호출하는 **WebMCP**
- 한 쪽 입장: AI가 사람처럼 웹을 탐색하는 건 **매우 비효율적**이라서 WebMCP가 맞다고 봄
- 반대 입장: 웹사이트를 운영하는 목적(교육, 업무 처리)을 생각하면 **사용자 인터페이스의 대리인**으로서의 에이전트에도 여전히 가치가 있음

---

## 📣 주요 발표 내용
- **WebMCP**는 화면 렌더링 단계를 아예 건너뛰고 기저의 웹 코드와 API에 직접 접근함
- 그래서 사용자가 원하는 작업을 더 효율적으로 처리할 수 있다고 함
- 앞으로는 웹사이트가 **에이전트가 읽기 쉬운 형식**으로 설계될 것이라는 전망
- 에이전트용 웹사이트는 사람용 웹사이트처럼 보이지 않을 것이므로, 그런 사이트에서는 Computer use가 의미를 잃는다는 주장
- 반론: 웹사이트의 목적이 교육이나 업무 처리라면, UI를 대신 다루는 에이전트(Computer use 방식)도 계속 쓸모가 있음

---

## 💡 개발자 포인트
- 에이전트 연동을 고려한다면 사람용 UI와 별도로 **에이전트가 읽을 수 있는 인터페이스**(WebMCP 같은 구조화된 API 노출)를 준비할 필요가 있음
- 화면 기반 자동화(Computer use)는 범용적이지만 효율이 떨어지고, API 기반(WebMCP)은 효율적이지만 사이트 쪽에서 지원해야 함
- 두 방식은 서로 대체하기보다 함께 쓰는 관계에 가까움. 사이트의 목적(교육·업무 처리)에 맞춰 설계 방향을 정해야 함

> 원본 자막이 짧은 토론 클립 분량이라 WebMCP의 구체적인 API, 스펙, 사용법은 영상에 나오지 않습니다.
