## 📣 주요 발표 내용
- **Google Antigravity** 에서 스킬과 프롬프트로 에이전트 동작을 바꿔, 코딩 에이전트 대신 **학습용 튜터**로 사용하는 방법 시연 (스킬·프롬프트는 영상 설명란에 공개)
- 예제 앱 '렐름 오브 엘도리아' RPG 퀘스트 & 인벤토리 추적기 생성
- **X-ray 모드**: 부모 컴포넌트(파란 박스)와 자식 컴포넌트(녹색 블록)를 눈으로 구분해 볼 수 있음
- 레슨마다 **모호한 프롬프트 vs 아키텍트 수준 프롬프트**를 비교함
- 6개 레슨 구성:
  - **1. 컴포넌트와 경계**: 화면을 레고 블록처럼 부모-자식 트리 구조로 구성하며, 중첩·형제·재사용이 가능함
  - **2. Props와 로컬 상태**: 제목·위치 같은 정보는 부모가 `props`로 넘기고, 진행률 카운터는 카드별 **로컬 상태**로 둠. 컴포넌트 하나를 여러 번 렌더링해도 상태는 인스턴스마다 따로 유지됨
  - **3. 계산된 값(Computed/Derived State)**: '남은 수량'을 별도 상태로 두면 **동기화 오류**가 생김. `남은 수 = 목표 - 현재 수집 수` 처럼 원본 상태 하나에서 남은 수·완료 여부·완료율·진행 바를 계산함
  - **4. 동적 렌더링과 스타일링**: 보스 체력이 60 이하면 '흥분'(호박색), 30% 미만이면 '분노'(빨간 테두리 점멸)로 바꾸고, 체력 0이면 승리 배너를 띄우는 **조건부 렌더링** 예시
  - **5. 동적 액션과 이벤트**: 늑대 5마리를 잡아야 현상금 버튼이 활성화되고 5마리를 넘으면 처치 버튼이 비활성화됨. **이벤트는 자식에서 부모로 전파**됨
  - **6. 로컬 vs 글로벌 상태**: 통화·UI 테마(Parchment/Obsidian)·단위 전환은 **글로벌 상태 Provider**에 두고, 서로 관련 없는 형제 컴포넌트(헤더·퀘스트 보상·배낭)가 이를 구독함. 카드 노트 토글 같은 것은 로컬 상태로 둠

## 💡 개발자 포인트
- "버튼 작동하게 해줘", "점수 고쳐줘" 같은 모호한 프롬프트를 주면 에이전트가 **땜질 패치**를 계속 쌓아 버그가 다시 생기는 악순환이 됨
- 프롬프트에 **무엇을 props로 받을지, 무엇을 로컬 상태로 둘지, 무엇을 계산할지**를 명시할 것
  - 예: "퀘스트 제목·위치·난이도는 props로 전달하고, 진행률 카운터는 로컬 상태로 유지해 + 버튼을 누르면 해당 카드만 증가하게 해줘"
> ⚠️ 파생 값(남은 개수, 완료 상태 등)을 **별도 상태로 저장하지 말 것**. 관리할 상태가 늘어나 동기화 버그의 주요 원인이 됨
- 스타일 지시는 **조건 + 결과**로 구체적으로 쓸 것
  - 예: "보스 체력이 30% 미만이면 카드 테두리를 빨간색으로 점멸하고 페이즈 배지를 교체해줘"
- 버튼 활성화·비활성화 조건을 **상태 값 기준**으로 명시하면 경계값 버그(목표 초과 등)를 막을 수 있음
- 깊은 트리에서 props를 내려보내고 다시 끌어올리는 일(prop drilling)이 많으면 **글로벌 상태/Context**를 고려할 것. 단, 컴포넌트 전용 UI 상태는 로컬에 둘 것
- 정확한 프론트엔드 용어를 몰라도 개념만 설명하면 AI가 충분히 알아들음
