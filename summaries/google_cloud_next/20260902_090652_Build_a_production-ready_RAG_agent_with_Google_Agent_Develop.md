# Build a production-ready RAG agent with Google Agent Development Kit (ADK), Gemini, and Cloud Run

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=sWHMIjgcxEU
- **요약 일시**: 2026-09-02 09:06:52

---

## 🔑 핵심 요약
- **Google Agent Development Kit(ADK)**, **Gemini**, **Cloud Run**을 조합해 프로토타입을 넘어서는 프로덕션용 RAG 에이전트를 구축한다.
- 에이전트가 매장 메뉴의 가격·태그·알레르기 정보를 조회한 뒤 고객에게 근거 있는 바리스타 추천을 제공하도록 구성한다.
- 정적 JSON 데이터를 **Cloud Firestore**로 이전하고 임베딩과 최근접 이웃 벡터 검색을 적용해 동적인 검색 기반을 만든다.

---

## 📣 주요 발표 내용
- `Agent`는 모델의 추론, 도구 호출, 시스템 지침, 세션 상태, 오케스트레이션과 가드레일을 결합하는 핵심 구성 요소로 소개된다.
- **Gemini Flash**를 자연어 이해·추론·의도 분석을 담당하는 모델로 사용한다.
- 사용자 프롬프트에 따라 에이전트가 `get_menu` 같은 Python 함수를 호출해 매장 메뉴 데이터와 알레르기 정보를 검색한다.
- **Streamlit**으로 대화형 웹 UI를 구현하고, 애플리케이션 전체를 **Cloud Run** 컨테이너에서 실행한다.
- Cloud Run 소스 기반 배포에서 **Cloud Buildpacks**를 사용해 별도 Dockerfile 없이 애플리케이션을 배포한다.
- 전용 **IAM 서비스 계정**을 만들고 최소 권한 원칙을 적용해 엔터프라이즈 보안을 강화한다.
- Cloud Run은 0까지 자동 스케일링하고 기본 HTTPS 엔드포인트와 스트리밍 응답에 필요한 장기 연결을 지원한다.
- 전체 예제는 커피숍 여정을 따라가며 메뉴 추천 에이전트, 매장 위치 분석, 커피숍 관리자용 개인 에이전트로 확장된다.

## 💡 개발자 포인트
- 로컬에서 `prompt`를 보내 응답을 받는 수준과 프로덕션 서비스 사이에는 세션 상태 유지, API 자격 증명 보호, 사내 데이터 기반 응답이라는 **Day 2 운영 과제**가 있다.
- 에이전트는 모델만으로 완성되지 않으며, 실제 데이터에 연결하는 도구와 오케스트레이션·가드레일을 함께 설계해야 한다.
- 여러 Cloud Run 인스턴스에서 대화 상태를 유지해야 한다면 현재의 인메모리 러너 구조를 외부 영속 저장소와 함께 검토해야 한다.
- RAG 도구가 반환하는 데이터 범위와 검색 결과를 명확히 정의해야 모델의 환각을 줄이고 알레르기 정보 같은 민감한 추천 근거를 통제할 수 있다.
- 정적 JSON에서 Firestore로 전환할 때는 임베딩 생성, 벡터 인덱스 구성, 최근접 이웃 쿼리, 데이터 갱신 흐름을 함께 운영해야 한다.
- 프로덕션 배포에서는 애플리케이션 실행에 필요한 서비스만 활성화하고 전용 IAM 계정의 권한을 최소화해야 한다.

> 단순히 모델에 프롬프트를 전달하는 방식만으로는 프로덕션 요구사항을 충족하기 어렵다. 세션 상태, 인증 정보, 데이터 그라운딩, 권한 모델을 아키텍처 단계에서 함께 다뤄야 한다.
