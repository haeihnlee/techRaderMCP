# AI-powered observability & remediation with Google Gemini CLI and Dynatrace

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=UMPSZxQYQx4
- **요약 일시**: 2026-09-02 09:08:32

---

## 🔑 핵심 요약
- **Gemini CLI**와 **Dynatrace**를 연동해 운영 환경의 문제를 자연어로 탐색하고 원인을 분석합니다.
- 최근 8시간 동안 **EasyTravel 애플리케이션**의 `order controller` 서비스에서 반복된 산술 예외를 발견합니다.
- 코드 분석 결과 기능 플래그가 활성화될 때 의도적으로 0으로 나누는 예외가 발생하며, Gemini CLI가 기능 플래그 서비스에 직접 연결해 해당 플래그를 비활성화합니다.

---

## 📣 주요 발표 내용
- Gemini CLI에 환경 내 최근 8시간의 문제를 조회하도록 요청하면 Dynatrace가 감지한 주요 장애를 확인할 수 있습니다.
- Dynatrace의 관측 데이터에서 `order controller` 서비스의 반복적인 `ArithmeticException`과 0으로 나누기 문제를 식별합니다.
- Gemini CLI가 소스 코드 주석과 기능 플래그 상태를 함께 검토해 문제의 원인이 코드 결함인지 기능 플래그 설정인지 구분합니다.
- 사용자의 승인 후 Gemini CLI가 기능 플래그 서비스와 직접 상호작용해 문제를 유발한 플래그를 비활성화합니다.
- Dynatrace는 Google Cloud Marketplace에서 제공됩니다.

---

## 💡 개발자 포인트
- **관측성에서 조치까지의 흐름**을 자연어 인터페이스로 연결하면 로그·문제 분석·설정 변경 사이의 운영 시간을 줄일 수 있습니다.
- 기능 플래그가 의도적으로 예외를 발생시키는 실험 또는 장애 주입에 사용될 수 있으므로, 장애 원인 분석 시 코드뿐 아니라 플래그 상태와 변경 이력도 확인해야 합니다.
- 운영 환경의 설정을 자동 변경하는 작업은 영향 범위가 크므로, Gemini CLI가 제안한 조치를 검토하고 명시적으로 승인한 뒤 실행하는 방식이 안전합니다.

> 기능 플래그를 비활성화하면 즉시 장애를 완화할 수 있지만, 근본적인 코드 문제를 해결한 것은 아닙니다. 사후에 예외 발생 경로를 수정하고 관련 테스트를 추가해야 합니다.
