## 🔑 핵심 요약
- **Looker CLI**(Go 기반)와 **Looker 스킬**, AI 에이전트를 함께 써서 여러 프로젝트에 걸친 감사·최적화를 자동화
- 거버넌스를 위해 CLI 셸 권한을 통째로 주지 말고 **MCP**로 API 범위를 좁힌 도구를 노출하도록 권장
- 사용자 속성 동기화를 에이전트에 맡기면 **행 수준 보안(row-level)** 파이프라인을 수동 작업 없이 운영 가능
- Looker 스킬은 **오픈 소스**라서 팀 워크플로우에 맞게 고쳐 쓸 수 있음

---

## 📣 주요 발표 내용
- **Looker CLI**: Looker API를 노출하는 Go 기반 도구. 여러 프로젝트의 반복 작업을 자동화
- **Looker 감사 스킬(Audit)**: 인스턴스 전체의 성능 병목, 운영 비효율, 거버넌스 공백을 진단
- 감사 스킬은 쿼리, **타일 밀도**, **캐싱 안티패턴**을 분석해 CLI 수정 레시피가 담긴 상태 보고서를 생성
- **Looker 성능 최적화 스킬**: 생성된 SQL을 프로파일링해 DB 병목을 찾고 LookML을 리팩토링
- 최적화 스킬이 하는 일: 캐싱 개선, 불필요한 조인 제거, 무거운 워크로드를 **PDT(Persistent Derived Table)**로 전환
- 스킬은 필요할 때까지 **메타데이터만 로드**하므로 LLM 토큰 사용량이 줄어듦
- 행 수준 파이프라인 예시: 에이전트가 CRM이나 인사팀 시트에서 사용자 명단·지역 정보를 읽어 사용자 속성을 일괄 동기화

---

## 💡 개발자 포인트
- 에이전트에 권한을 줄 때 셸 전체 대신 **MCP로 범위를 좁힌 API 도구**만 열어 최소 권한 원칙을 지킬 것
> ⚠️ 사용자가 수천 명인 환경에서 UI로 그룹·속성을 손으로 관리하면 운영 부채가 쌓이고, 액세스 오류나 **데이터 유출**로 이어질 수 있음
- 사용자 속성을 LookML `access_filter`나 SQL 파라미터 주입에 연결해 두면, 속성이 바뀌는 즉시 쿼리 컴파일러가 조건을 자동으로 붙임 (예: `region = 'US_Northeast'`)
- 속성 동기화는 프로그래밍 방식(CRM 연동)이나 이메일로 받은 시트를 계기로 실행할 수 있음
- Looker를 로컬 스크립트와 에이전트 하네스에 연결하면, 대시보드 도구를 넘어 인프라처럼 관리되는 **헤드리스 거버넌스 서비스**로 쓸 수 있음
- 오픈 소스 스킬 저장소를 포크해 팀 규칙에 맞게 수정할 수 있고, PR과 이슈로 기여할 수 있음
