# How to modernize legacy codebases using AI coding agents (Step by step guide)

## 🔑 핵심 요약
- **AI 코딩 에이전트**를 활용해 레거시 코드베이스를 체계적으로 현대화하는 3단계 접근법: **Plan → Execute → Verify**
- 에이전트에게 `README`로 로컬 도구(컴파일러·린터·테스트) 실행 방법을 명확히 문서화하면 자가 수정 피드백 루프가 형성됨
- 코드 작성은 저렴해졌지만, 좋은 소프트웨어를 만드는 것은 여전히 설계 역량이 핵심

---

## 📣 주요 발표 내용
- **Change Request 중심 학습**: 전체 코드베이스를 미리 파악하지 않고, 변경이 필요할 때만 블록 단위로 학습하는 방식 권장
- **Planning Mode 우선 사용**: `Gemini CLI` / Antigravity IDE 등 AI 도구에서 코딩 전 반드시 탐색(Recon) 단계 먼저 실행 — 영향 받는 파일·API·DB 테이블을 미리 파악
- **AI를 자동 타이피스트가 아닌 동료로 대우**: 요구사항을 함께 논의하고, AI가 역으로 질문하도록 유도해 숨겨진 요구사항 발굴
- **TDD/BDD 선도**: Pro 모델로 인수 조건·테스트 초안 작성 → Flash(저비용 모델)로 구현 코드 생성 → 테스트 통과 후 다음 단계
- **3단계 검증 필터**: ① 인간 코드 리뷰 → ② CI/CD 내 보조 AI 모델 PR 리뷰 → ③ 스테이징 스모크 테스트

---

## 💡 개발자 포인트
- `README`에 `docker`, 린터, 유닛 테스트 실행 명령을 명시해두면 AI 에이전트가 스스로 빌드-테스트-수정 루프를 돌 수 있음
- **Docker를 disposable sandbox**로 활용 — AI가 만든 변경사항을 격리, `docker rm`으로 초기화 가능
- 긴 멀티태스크 세션에서 AI는 맥락을 잃기 쉬움 → 큰 변경은 서브태스크로 분리하고, 진행 상황을 **마크다운 체크리스트 파일**로 유지
- **Agent Rules(프로젝트 규칙)** 설정으로 팀 전체에 일관된 워크플로우 강제 가능 (`테스트 먼저 작성`, `커밋 전 허가 필요` 등)

> **주의**: AI에게 프로덕션 직접 배포 권한을 주지 말 것. 반드시 인간 검토 + 자동화 검증 + 스테이징 테스트를 거쳐야 함.

- 신기능 설계 시 AI에게 **3가지 아키텍처 옵션**을 생성시키고 스스로 비판하게 한 뒤 선택하는 방식 효과적
- 버그 수정 시: 문제 설명 → 구체적 예시 제시 → AI가 실패 테스트 작성 → 구현 순서를 따를 것
