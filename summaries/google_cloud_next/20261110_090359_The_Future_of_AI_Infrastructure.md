## 🔑 핵심 요약
- Google AI·인프라 조직 총괄 Amin Vahdat가 **에이전트 시대의 AI 인프라** 방향을 발표했습니다. 사람 단위에서 에이전트 단위로, 기록 시스템에서 행동 시스템으로, 단순 요청에서 복잡한 에이전트 워크플로로 수요가 바뀐다는 내용입니다.
- **8세대 TPU**는 두 종류입니다. 하나는 학습용, 다른 하나는 실시간 추론용입니다(자막에 `TPU 80`/`aitai`로 표기되어 있으며 **TPU 8i**로 추정). 추론용은 **Boardfly** 토폴로지, **HBM 288GB**, **SRAM 3배**를 적용해 저지연 서빙 가성비를 최대 80% 높였습니다.
- **Project Suncatcher**로 TPU를 실은 시제품 위성을 저궤도에 올렸고, 궤도 위에서 첫 추론("Hello World")에 성공했습니다.

> ℹ️ 원본 자막이 12,000자에서 잘려 있습니다. 발표 후반부(세 번째 병목 이후)는 이 요약에 포함되지 않았습니다.

## 📣 주요 발표 내용
- **Gemini의 범용 AI 에이전트화**: 목표를 받으면 서브에이전트를 만들고, 시스템 조회와 도구 조율을 하면서 여러 날에 걸친 작업을 수행합니다.
- **AI Hypercomputer**: 데이터센터, 컴퓨팅 프로비저닝, 네트워킹, 스토리지, 실리콘, 런타임, 프레임워크를 처음부터 **함께 설계(co-design)**한 시스템입니다. 모든 계층이 개방되어 있습니다.
- **학습용 8세대 TPU 보드**:
  - 컴퓨트 칩 2개와 **HBM3E 12스택**이 올라갑니다.
  - ICI(칩 간 인터커넥트)는 칩당 양방향 **19.2Tbps**로 이전 세대의 2배입니다.
  - 광 트랜시버까지 **처음으로 액체 냉각**합니다.
- **9,600칩 슈퍼팟**: 컴퓨팅 성능이 약 3배 높고, 학습 비용은 **2.7배 낮습니다**. 학습 기간이 수개월에서 수주로 줄어듭니다.
- **Boardfly 토폴로지**(추론용 TPU):
  - 계층형 저직경(low-diameter) 메시 구조입니다.
  - 기존 3D torus의 최악 경로가 **16홉**이었는데 이를 **7홉**으로 줄였습니다.
  - 칩 간 통신 지연이 최대 절반으로 줄었습니다.
- **메모리 벽 대응**(추론용 TPU):
  - HBM을 50% 늘려 **288GB**가 되었습니다.
  - 칩에 올라가는 SRAM을 3배로 늘려 **KV 캐시**를 칩 위에 둡니다.
- **TPU 설계 6원칙**:
  - 적은 수의 큰 코어를 쓰고, 컴파일러가 실행을 정적으로 스케줄링합니다.
  - **systolic array**를 씁니다.
  - 하드웨어 캐시 대신 **컴파일러가 제어하는 메모리**를 씁니다.
  - **OCS**(광 회로 스위치)로 칩을 연결합니다.
  - `bfloat16`, **Native FP4** 같은 저정밀 포맷을 쓰면서도 비트 단위 결정성을 유지합니다.
  - **액체 냉각 콜드플레이트**를 씁니다.
- **Project Suncatcher**:
  - 궤도 위 TPU에서 ML 테스트와 추론을 하고, 결과를 지상에서 검증했습니다.
  - 내년에 위성 2기를 쏘아 **위성 간 레이저 링크**를 시험할 예정입니다.

## 💡 개발자 포인트
- **에이전트 워크로드는 토큰을 훨씬 많이 씁니다.**
  - 사람과 AI의 대화 한 번은 약 1,000토큰입니다.
  - 같은 작업을 에이전트가 하면 수십 개의 서브에이전트와 수백 번의 모델 호출로 **수백만 토큰**이 듭니다.
  - 비용과 지연을 설계할 때 **추론 루프 횟수**를 우선 지표로 삼아야 합니다.
- **추론이 AI 컴퓨팅의 50~70%를 차지합니다.** 서빙 비용 최적화(모델 크기, 양자화, KV 캐시 전략)가 학습보다 중요해지고 있습니다.
- 모델을 여러 칩에 나눠 올리면 토큰마다 칩끼리 부분합을 주고받아야 합니다. 그래서 **네트워크 홉 수가 곧 토큰 생성 지연**이 됩니다. 텐서 병렬 서빙에서는 토폴로지를 반드시 고려해야 합니다.
- **긴 컨텍스트에서는 메모리 대역폭이 병목**입니다. 백만 토큰 컨텍스트나 에이전트 다수를 병렬로 돌릴 때 고객은 세 가지 중 하나를 골라야 했습니다.
  - 컨텍스트를 자른다.
  - 동시에 돌리는 에이전트 수를 줄인다.
  - 지연을 감수한다.

  HBM과 SRAM이 늘어난 추론 전용 TPU는 이 문제를 겨냥합니다.
- **기업 도입 시 병목**:
  - 규제 산업은 사용 중인 데이터를 **하드웨어 수준에서 암호화**해야 합니다.
  - AI 빌더는 **추론과 RL을 같은 실리콘**에서 돌리는 통합 클러스터가 필요합니다.
- **FP4 등 저정밀 포맷**을 하드웨어가 기본 지원하므로, 양자화 모델을 서빙할 때 Watt당 성능이 좋아질 것으로 기대됩니다.

> ⚠️ 자막이 음성 인식으로 만들어져 제품명이 정확하지 않을 수 있습니다(예: `TPU 80`/`aitai` → TPU 8i로 추정, `board fly` → Boardfly). 정확한 명칭은 공식 문서에서 확인하세요.

## 📅 버전 / 출시 일정

| 항목 | 내용 |
| --- | --- |
| TPU v1 | 2015년 출시, 공랭식 75W PCIe 카드, 15개월 만에 개발 |
| TPU 개발 계기 | 2013년 Google 음성 검색에 신경망 도입, 당시 비교 프로세서 대비 처리량 30배 |
| 8세대 TPU(학습용/추론용) | 올해 초 발표 |
| Project Suncatcher 시제품 위성 | 지난달 발사, 발표 시점 기준 궤도 운용 4주차 |
| Suncatcher 위성 2기 | 내년 발사 예정(위성 간 레이저 링크 시험) |
| 에이전트 트래픽 증가 | 최근 1년간 7,800% 이상 |
| 추론 비중 | 2년 전 40%에서 현재 50~70% |
| 글로벌 토큰 수요 예측 | 2030년까지 24배, 월 120경(quadrillion) 토큰 이상 |
| 9,600칩 슈퍼팟 | 컴퓨팅 성능 약 3배, 비용 2.7배 절감 |
| 추론용 TPU | HBM 288GB(+50%), SRAM 3배, 최대 홉 16→7, 가성비 최대 80% 향상 |
