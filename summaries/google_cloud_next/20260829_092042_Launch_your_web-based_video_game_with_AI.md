# Launch your web-based video game with AI

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=t4LOHNHv-r8
- **요약 일시**: 2026-08-29 09:20:42

---

## 🔑 핵심 요약
- **Google AI Studio Build mode**로 별도 LLM 호출 없이 웹 기반 턴제 게임을 빠르게 만들고 `Cloud Run`에 배포하는 과정을 소개합니다.
- 게임 상태를 덮어쓰지 않고 모든 플레이를 이벤트로 저장하는 **이벤트 소싱(event sourcing)**으로 실행 취소와 리플레이를 구현합니다.
- `Firestore`의 실시간 동기화를 활용해 별도 동기화 서버 없이 여러 플레이어가 실시간 온라인 대전을 진행할 수 있습니다.

---

## 📣 주요 발표 내용
- `Firestore`에 게임 문서와 append-only `events` 서브컬렉션을 저장해 매 턴의 플레이를 순서대로 기록합니다.
- 저장된 이벤트의 `sequence`를 정렬하고 순차적으로 재생해 현재 게임 상태를 복원합니다.
- 틱택토 예제에는 `Minimax` 알고리즘 기반의 상대 플레이어가 포함됩니다.
- `Google` 인증 사용자와 게스트 플레이어가 매치를 생성하고 공유 링크 또는 매치 코드로 참여할 수 있습니다.
- `Firestore` 실시간 동기화 덕분에 서로 다른 기기와 지역의 플레이어 사이에도 게임 상태가 즉시 반영됩니다.
- `AI Studio`에서 자연어로 기능과 오류를 설명하고, 필요한 `Firestore Security Rules` 수정 및 버그 수정을 수행합니다.
- 수정 후 `Cloud Run`에 재배포하고, `Firebase Console`에서 `games`와 `events` 컬렉션을 직접 점검하는 개발 흐름을 보여줍니다.

---

## 💡 개발자 포인트
- 이벤트 소싱은 현재 상태만 저장하는 방식보다 데이터 구조가 복잡하지만, **undo·replay·감사 로그·상태 재구성**이 필요한 게임에 적합합니다.
- 이벤트는 append-only로 유지하고 `sequence` 같은 순서 필드를 두면 동시성 상황에서도 게임 진행을 재구성하기 쉽습니다.
- `Firestore Security Rules`는 기본적으로 매우 제한적으로 생성되므로, 권한 오류가 발생하면 무작정 전체 공개하지 말고 필요한 작업 단위만 점진적으로 허용해야 합니다.

> `Firestore` 규칙을 전체 공개로 완화하면 악의적인 사용자가 데이터베이스를 임의로 변경할 수 있습니다. 인증 사용자와 게스트의 읽기·쓰기 범위를 게임 문서 및 이벤트 단위로 최소화하세요.

- 프로덕션 배포 후에는 호스트와 게스트를 서로 다른 브라우저에서 실제로 테스트해 턴 권한과 실시간 상태 동기화를 검증해야 합니다.
- 배포 뒤 발견한 게스트 플레이어 오류처럼, 정확한 에러 메시지를 그대로 `AI Studio`에 전달하면 소스 추적과 수정에 도움이 됩니다.
- LLM 기반 기능은 이번 예제 범위에 포함되지 않으며, 향후 `Firebase`의 관련 기능을 통해 애플리케이션 내부 LLM 호출을 추가할 수 있습니다.
