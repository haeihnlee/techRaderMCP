## 🔑 핵심 요약
- **에이전트 = LLM + 에이전트 하네스**: LLM 주변의 모든 것(도구, 컨텍스트, 환경)이 하네스
- 프롬프트에 내용을 직접 채우는 대신, 모델이 스스로 컨텍스트를 찾을 수 있는 **환경을 구성**하는 것이 핵심
- 작은 변경 → 반복 신뢰 구축 → 점진적으로 더 넓은 범위의 자율성을 부여하는 **루프 확장 전략**

---

## 📣 주요 발표 내용
- **에이전트 하네스** 개념: Google의 Ryan Lopopolo가 명명한 용어로, AI 에이전트에서 LLM을 제외한 모든 것을 의미
  - 예: Gemini Flash = 모델, Google Antigravity = 하네스
- **"Lazy Prompting"** 철학: 모델에게 도구와 컨텍스트를 제대로 제공했다면, 프롬프트 자체를 최소화해도 됨
- **"Shifting Left"** 전략: 모델에 대한 개입을 가능한 소프트웨어 개발 프로세스의 앞쪽(왼쪽)으로 이동
  - 우: 프롬프트만 수정
  - 좌: 문서 추가 → 정적 검증기 → 테스트 → 에이전트용 자동화 컨텍스트
- **PromQL 스타일 옵저버빌리티**: 모델 학습 데이터에 잘 표현된 도구일수록 에이전트가 잘 활용함
- **마크다운 링크 최적화**: 링크를 인라인 텍스트 흐름에 넣지 않고 문단/리스트 끝에 named anchor로 배치 → 컨텍스트 효율 + 가독성 동시 확보

## 💡 개발자 포인트
- **에이전트의 자율성을 높이는 방법**: 프롬프트에 지시를 채우기보다 에이전트가 스스로 컨텍스트를 발견할 수 있도록 환경 설계
- **코드 리뷰 가능한 작은 PR**: 에이전트가 쌓아올리는 변경을 검증하려면 리뷰하기 쉬운 단위가 필수
- **모델이 좋아지는 것과 "내가 원하는 것을 아는 것"은 별개**: 모델 성능 향상과 별개로, 컨텍스트 큐레이션은 계속 엔지니어링해야 함

> ⚠️ "모델이 점점 더 똑똑해진다고 해서 기본적으로 내가 원하는 것을 더 잘 알게 되지는 않는다" — 하네스 엔지니어링의 핵심 통찰

- **신뢰 스태킹**: 작은 변경에서 신뢰를 쌓으면, 더 야심찬 변경(언어 전체 마이그레이션 등)도 자동화 가능해짐
- **에이전트 감독 방법**: 실행 로그가 아닌 최종 산출물(코드, 문서, 스프레드시트)을 보고 판단
