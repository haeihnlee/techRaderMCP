# Cloud Load Balancing explained: How does global traffic routing work behind a single IP address?

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=Wg_iHWlSu4A
- **요약 일시**: 2026-11-04 09:04:54

---

## 🔑 핵심 요약
- **Cloud Load Balancing**은 웹사이트 앞단에서 요청을 여러 복제 서버로 분산하는 **트래픽 관리자**
- 전 세계 사용자는 **단일 Anycast IP** 하나로 접속하고, 실제 처리는 가장 가까운 리전의 서버가 담당
- 헬스 체크, 자동 장애 우회, **웜업 없는 즉시 확장**, 리전 간 오버플로로 트래픽 급증에도 서비스 유지

---

## 📣 주요 발표 내용
- 서버 한 대로는 트래픽 급증 시 지연 → 과부하 → 다운으로 이어지는 문제를 설명
- 로드 밸런서가 모든 요청을 먼저 받아 **동일한 복제 서버 여러 대**로 분산
- 각 백엔드의 상태를 지속적으로 확인하는 **헬스 체크** 수행
- 응답하지 않는 서버는 자동으로 제외하고 우회 → 사용자는 장애를 인지하지 못함
- **글로벌 Anycast IP**: 전 세계에 하나의 주소를 노출하고 사용자를 가장 가까운 리전으로 라우팅
- **웜업(pre-warming) 없이** 수 초 안에 급증한 트래픽 처리
- 특정 리전 용량이 가득 차면 여유 있는 다른 리전으로 트래픽 **오버플로**

---

## 💡 개발자 포인트
- 단일 서버 구조 대신 **수평 확장(복제 백엔드) + 로드 밸런서** 구조를 전제로 설계할 것
- 백엔드는 **stateless**하게 만들어야 어느 서버로 라우팅돼도 동일하게 응답 가능
- 헬스 체크 엔드포인트(예: `/healthz`)를 제공해야 자동 장애 우회가 제대로 동작
- 글로벌 서비스라면 멀티 리전 백엔드를 배치해 **지연 시간 감소**와 **리전 장애 대응**을 함께 확보
- DNS 기반 분산과 달리 **Anycast IP** 하나로 처리되므로 클라이언트·DNS 설정이 단순해짐
> 이 영상은 개념 소개용 입문 영상이며, 구체적인 설정 방법·가격·제품 SKU(예: Application/Network LB 구분)는 다루지 않음
