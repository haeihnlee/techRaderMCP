# Ground AI Agents with Looker and Knowledge Catalog on Google Cloud

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=QsGQQYj1vEY
- **요약 일시**: 2026-11-18 09:04:03

---

## 🔑 핵심 요약
- **Looker**(시맨틱 계층 + SQL 엔진)를 **Knowledge Catalog**(범용 컨텍스트 계층)와 통합하면 AI 에이전트가 정확한 비즈니스 컨텍스트와 거버넌스를 기반으로 답변할 수 있음
- 원시 SQL을 직접 작성하는 **baseline agent**는 도메인 규칙을 몰라 추측·오답을 내지만, **거버넌스 기반 Looker 에이전트**는 메타데이터로 정확한 답을 더 적은 턴·토큰으로 생성
- PII 태그 기반 자동 마스킹, 정형(Looker) + 비정형(PDF) 데이터 결합 질의까지 지원

---

## 📣 주요 발표 내용
- Looker ↔ Knowledge Catalog 통합 시 **LookML 모델, Explore, View, Dashboard** 자산이 자동 색인되어 Google Cloud 콘솔에서 검색 가능
- **Knowledge Studio**의 탐색 에이전트가 자연어 요청에 따라 **시각적 컨텍스트 그래프**를 동적으로 구축
- **업스트림 리니지** 추적: Dashboard → Explore → View → **BigQuery** 소스 테이블까지 역추적
- 노드 클릭 시 대시보드 ID, 폴더 ID, 작성자 이메일 등 메타데이터와 조인 관계, 차원·측정값의 LookML 로직(예: `case` 문) 확인 가능
- Gemini 상에서 에이전트가 응답과 함께 **Looker Explore 링크**를 생성 → 필터 조정, 드릴다운, Slack 전송 등 후속 탐색 가능
- Knowledge Catalog에서 필드를 **PII/민감 데이터로 태그**하면 에이전트가 정책을 확인해 자동으로 가림/숨김 처리
- Cloud Storage에 업로드되어 Knowledge Catalog에 인덱싱된 **PDF(비정형 데이터)**와 Looker 실시간 데이터를 결합해 답변 (예: 지원금 대상자 식별 및 지급액 계산)

## 💡 개발자 포인트
- 에이전트 품질은 **제공되는 컨텍스트**가 좌우함 → 원시 테이블 직접 쿼리보다 시맨틱 계층을 거치게 설계할 것
> ⚠️ 주의: baseline agent는 "50세 이하 팀 부문 = 31~50세" 같은 도메인 규칙을 몰라 스키마 탐색에 여러 턴을 소모하고, 존재하지 않는다고 하거나 잘못된 연령대(41~50세)를 적용함. 분석가는 이런 오류를 알아채기 어려움
- 거버넌스 기반 에이전트 구조: **LLM은 텍스트 → 의도 변환**만 담당, **SQL 생성은 Looker**가 담당 → 결정적이고 최적화된 쿼리, 토큰 절감
- 리니지 그래프는 컬럼 이름 변경·삭제 등 **업스트림 스키마 변경 전 영향도 분석**에 유용
- 개인정보 보호는 프롬프트가 아니라 **카탈로그 태그(메타데이터) 수준**에서 정책으로 관리 가능
- 정형·비정형 데이터를 하나의 카탈로그로 통합하면 단일 소스만으로는 답할 수 없던 질문에 대응 가능
