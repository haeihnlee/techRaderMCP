# What "one agent, everywhere you work" actually means

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=VI3TQriNq_E
- **요약 일시**: 2026-10-28 09:03:29

---

## 🔑 핵심 요약
- "One agent"는 서로 연결되지 않은 **stateless 채팅 탭**이 아니라 **항상 켜져 있는(always-on) 전용 에이전트**를 뜻함
- 에이전트는 클라우드의 **단일 중앙 집중형 브레인(centralized brain)** 하나로 동작함
- Google Docs, 노트북, 모바일 앱, 커맨드라인 중 어디서 요청하든 **같은 에이전트**로 라우팅되고 **하나의 연속된 실행(continuous execution)**에 기록됨

> 주의: 추출된 자막이 짧아서(영상 앞부분만 확보됨) 이 요약은 아키텍처 개념 설명 부분만 다룹니다. 발표 뒷부분 내용은 빠져 있습니다.

---

## 📣 주요 발표 내용
- 세션 단위로 따로 만들어지는 stateless 채팅에서 **상시 실행되는 전용 에이전트** 모델로 전환
- 모든 사용 위치의 요청을 클라우드의 **단일 에이전트 인스턴스**로 라우팅
- 지원 위치로 언급된 곳: **Google Docs**, 데스크톱(노트북), **모바일 앱**, **커맨드라인(CLI)**
- 모든 요청이 **하나의 연속된 실행 흐름**에 쌓이고, 히스토리(History)도 이 흐름에서 이어지는 것으로 언급됨

---

## 💡 개발자 포인트
- 에이전트 상태와 컨텍스트를 클라이언트가 아니라 **서버(클라우드) 쪽에 중앙 집중**하는 설계라서, 클라이언트는 얇은 진입점 역할만 함
- 여러 곳(문서 편집기, CLI, 모바일)에서 같은 작업 맥락을 이어받을 수 있으므로, 연동할 때는 **세션 관리보다 단일 실행 기록 기준**으로 생각하는 편이 맞음
- 연동 앱을 만든다면 요청이 **동일 에이전트로 라우팅되는 구조**를 전제로 동시성과 순서 처리를 고려해야 함

> 구체적인 API, SDK 이름, 플래그는 추출된 자막 범위에서 언급되지 않았습니다.
