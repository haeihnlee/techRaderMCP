> ⚠️ 영상 제목은 "Chatbots vs. workflows vs. agents"이지만, 추출된 자막은 **AI 에이전트의 3가지 메모리 계층**(상태 / 세션 / 장기 기억)을 다룹니다. 이 요약은 자막 내용을 기준으로 작성했습니다.

## 🔑 핵심 요약
- AI 에이전트의 맥락 관리는 **상태(State)**, **세션(Session)**, **장기 기억(Long-term Memory)** 의 3계층으로 나뉩니다.
- **ADK**(자막에는 "80K"로 표기, ADK의 음성 인식 오류로 보임)는 대화 단위 맥락을 위한 **세션 서비스**와 세션 간 맥락을 위한 **메모리 서비스**를 분리해 제공합니다.
- 계층마다 역할이 다릅니다. 상태는 지금 하는 작업, 세션은 현재 대화, 장기 기억은 다음 대화로 넘겨줄 정보를 담당합니다.

---

## 📣 주요 발표 내용
- **상태(State)**: 에이전트의 작업 기억(working memory)입니다. 예를 들어 남은 여행 예산이나 현재 여행 계획처럼 당장 필요한 값을 담습니다.
- 상태는 시스템 구성 요소끼리 중요한 정보를 주고받는 **공유 메모장** 역할을 하며, 계획이 바뀌면 함께 갱신됩니다.
- **세션(Session)**: 하나의 대화 스레드에 대한 전체 기록입니다. 메시지, 도구 호출, 도구 결과, 상태가 모두 포함됩니다.
- **세션 서비스**는 세션의 저장과 불러오기를 맡습니다.
- 세션 백엔드 선택지
  - **인메모리(RAM)**: 빠르고 간단하지만 서버를 재시작하면 사라집니다.
  - **영구 데이터베이스**: 서버를 재시작해도 세션이 남아 있어 나중에 대화를 이어갈 수 있습니다.
- **장기 기억(Long-term Memory)**: 여러 대화에 걸쳐 유용한 정보를 넘겨줍니다.
- **메모리 서비스**는 정보를 저장·검색하고, 관련 기억을 새 대화의 맥락에 넣어 줍니다. 예를 들어 사용자가 "조용한 동네 선호"라고 말하면 다음 여행 계획에 이 정보가 반영됩니다.

## 💡 개발자 포인트
- 에이전트를 설계할 때 데이터 수명에 따라 저장 위치를 나누세요. 현재 작업 값은 `state`에, 대화 기록은 `SessionService`에, 사용자 선호처럼 다음 세션에도 필요한 정보는 `MemoryService`에 둡니다.
- 프로토타입 단계에서는 인메모리 세션 백엔드로 충분합니다.

> **주의**: **장시간 실행되는 프로세스**나 운영 환경에서 인메모리 세션만 쓰면 서버를 재시작할 때 대화 맥락이 모두 사라집니다. 이런 환경에는 영구 DB 백엔드가 꼭 필요합니다.

- 세션 서비스는 세션 하나 안의 맥락을, 메모리 서비스는 **세션 간** 맥락을 다룹니다. 두 서비스를 섞지 말고 역할을 나눠 쓰는 것이 좋습니다.
- 장기 기억은 저장만으로 끝나지 않습니다. 관련 기억을 검색해 맥락에 넣는 단계까지 설계해야 합니다.
