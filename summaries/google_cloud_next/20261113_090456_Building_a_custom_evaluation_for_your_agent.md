# Building a custom evaluation for your agent

- **출처**: https://www.youtube.com/watch?v=GatM9XV0gOw
- **요약 일시**: 2026-11-13 09:04:56

---

## 🔑 핵심 요약
- Google **ADK(Agent Development Kit)** 로 AI 에이전트를 평가하고, Python으로 **커스텀 평가 지표(custom metric)** 를 직접 만드는 방법을 단체 식사 추천 에이전트 예제로 설명
- 평가 방식은 **비교기(comparator, 참조 정답과 비교)** 와 **체커(checker, 요구사항 직접 검증)** 두 가지로 나뉘고, 각각 **코드 규칙** 또는 **LLM-as-a-Judge** 로 구현할 수 있음
- 체커를 먼저 정답을 아는 예시로 검증하고, 그다음 `adk eval` CLI·웹 UI·`pytest` 로 실행해 **CI/CD 배포 게이트** 로 연결

---

## 📣 주요 발표 내용
- **무엇을 평가할지**: 최종 결과가 유효한지, 그리고 그 결과까지 가는 **궤적(trajectory)**(도구 호출 순서, 예: 예약 전에 식단 확인)이 올바른지 둘 다 봐야 함
- LLM은 실행할 때마다 결과가 다를 수 있으므로, 결과가 달라도 요구사항을 충족하면 **둘 다 성공** 으로 처리해야 함
- 멀티턴 대화에서는 앞에서 말한 요구사항을 계속 **기억하는지** 도 평가 대상
- ADK 내장 지표:
  - 참조 답변과의 **문구 중복도** 측정
  - LLM이 참조 답변과 **의미** 를 비교
  - 실제 도구 호출과 예상 호출을 **인자까지 포함해** 비교 (순서 일치 엄격도 선택 가능)
  - 응답·멀티턴 대화용 **루브릭 기반 모델 판정기** (루브릭만 직접 작성)
- **골든 데이터셋**: 신뢰할 수 있는 정답이 붙은 테스트 요청 모음. 다만 그룹 구성이 바뀔 때마다 가능한 정답을 모두 나열하기는 현실적으로 어려움 → 이런 경우 **체커** 가 더 적합
- 코드 규칙은 같은 입력에 항상 같은 결과를 내고(결정적), LLM 판사는 "설명이 명확한가"처럼 **해석이 필요한 요구사항** 에 적합. LLM 판사의 판단도 검토한 예시로 검증해야 함

## 💡 개발자 포인트
- **커스텀 지표 함수 구성 흐름**
  - ADK가 기록된 에이전트 상호작용과 평가 설정을 함수에 전달
  - 저장된 그룹 ID로 그룹 요구사항 조회 → 에이전트가 반환한 **JSON** 필드에서 식당·시간 추출
  - 값이 없거나 모르는 식당이면 **즉시 실패** 처리 (평가기가 빠진 계획을 임의로 채우면 안 됨)
  - 1인당 식단·알레르기·예산·거리·매운맛 선호·시간을 모두 확인하고, 계획이 맞는 인원 ÷ 전체 인원으로 점수 계산
  - 점수와 임계값을 비교해 **평가 결과 객체**(전체 결과 + 턴별 결과) 반환, 실패 원인은 별도 세부 파일에 기록
- **평가 구성 파일(JSON)**: 기준(criteria) 섹션에 지표와 임계값을 설정하고, **custom metrics 섹션** 에 Python 프로젝트 안 함수 위치를 등록
- **평가 세트 파일(JSON)**: 테스트할 요청(사례)을 정의. 평가 구성 파일은 평가 방법을 정의
- 실행 방법:
  - CLI: `adk eval` 에 에이전트, 평가 구성 파일, 평가 세트 JSON을 지정
  - 웹 UI: 커스텀 지표 등록 → 지표 목록에서 선택 → 임계값 설정 후 실행, 평가된 대화 확인
  - `pytest`: 두 JSON을 불러와 에이전트 평가자 호출 → 평가가 실패하면 테스트도 실패 → CI/CD 파이프라인에 추가

> ⚠️ 체커로 에이전트를 평가하기 전에 **체커 자체를 먼저 테스트** 할 것: 6명 중 3명만 만족하면 0.5점으로 실패, 맞는 계획은 1점으로 통과, 불완전한 답변은 항상 실패해야 함

> ⚠️ 한 번 실행해서는 일관성을 알 수 없으므로 중요한 사례는 **반복 실행** 하고, 새로 발견한 실패는 **회귀 테스트 사례로 저장**. 에이전트 버전끼리 비교하려면 사례와 성공 기준을 그대로 유지해야 함

- 데모에서는 에이전트가 그룹 제약보다 **식당 평점을 우선** 하도록 설정되어 있어 0.5점으로 실패 → 세부 파일에 채식·알레르기·시간 문제가 드러나 개선 근거가 됨

| 항목 | 값 |
| --- | --- |
| 데모 그룹 인원 | 6명 |
| 3명 충족 시 점수 | 0.5 (실패) |
| 전원 충족 시 점수 | 1.0 (통과) |
| 통과 임계값 | 1.0 |
