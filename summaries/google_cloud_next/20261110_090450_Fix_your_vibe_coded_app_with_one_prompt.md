# Fix your vibe coded app with one prompt

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=ivW7cqypZEY
- **요약 일시**: 2026-11-10 09:04:50

---

## 🔑 핵심 요약
- 바이브 코딩으로 버그를 하나씩 고치면 **하나를 고칠 때 둘이 새로 생기는 악순환**에 빠지기 쉬움
- 해결책: 변경 목록 대신 화면 전체를 **하나의 시스템(상태 머신)**으로 정의한 사양을 작성해 한 번에 적용
- 사양 → **Gemini로 테스트 케이스 생성** → **Google Antigravity**에서 "모든 테스트 통과 전까지 미완료" 조건으로 구현 → 약 7분 만에 의도대로 동작

---

## 📣 주요 발표 내용
- 예제: 스마트 개인 트레이너 앱의 **활성 운동 화면**(AI 없는 영역) UX 개선 ('Build it' 시리즈, 진행자 Devin)
- 기존 문제: 휴식 타이머 '건너뛰기' 후에도 같은 세트에 머무름, 중복 버튼, 슈퍼세트에서 '다음 세트' 흐름이 맞지 않음
- 사양을 5개 섹션으로 구조화:
  - **표시 변경**: 버튼 텍스트·레이아웃 등 단순 수정
  - **구성 요소**: 화면을 이루는 컴포넌트 목록 (코드 구조와 LLM의 사고 방식에 맞춤)
  - **변수(상태)**: `currentSet`, `isRestMode`, 첫 세트/마지막 세트 여부(페이지 수준), 세트 완료 여부(컴포넌트 수준)
  - **표시 로직**: "휴식 모드면 A 표시·B 숨김"처럼 모든 상태 조합을 **간결하게, 빠짐없이** 정의
  - **액션 로직**: '세트 완료' 클릭 시 일반 케이스와 마지막 세트 케이스를 나눠 처리
- 마지막 세트 완료 후 "세트는 끝났지만 운동 기록은 아직 저장 안 됨"을 나타내는 **특수 값(placeholder)** 상태 도입
- 결과 화면: 휴식 모드에서는 타이머(±30초)·다음 운동·운동 종료만 표시, 이전 세트 기록 조건부 표시, 다가올 세트 미리보기(최대 3개, 남은 세트 수만큼 축소), '다음 세트' 클릭 시 완료/건너뛰기(0 처리)/미리보기 메뉴 표시

## 💡 개발자 포인트
- 버그 목록을 나열하지 말고 **컴포넌트 / 상태 변수 / 표시 로직 / 액션 로직**으로 시스템을 정의하면 수정 사항끼리 충돌할 때 무엇이 우선인지 분명해짐
- 상태를 **페이지 수준과 컴포넌트 수준**으로 나누기: 페이지는 컴포넌트를 표시할지만 판단하고, 컴포넌트는 내부 표시를 판단 (예: 미완료 세트는 입력 필드 + '세트 완료', 완료된 세트는 텍스트 + '세트 편집')
- 경계 상태(마지막 세트 이후 등)는 **명시적인 특수 값**으로 모델링해야 엣지 케이스를 놓치지 않음
- 액션의 부수 효과 타이밍을 정의: 세트 완료 시 바로 `currentSet` 를 바꾸지 않고 **휴식이 끝난 뒤에** 넘김 (휴식 시간은 직전 세트와 연관되므로)
- 사양을 LLM에 넘겨 **"상태 X일 때 A는 보이고 B는 안 보여야 한다"** 형태의 검증 가능한 테스트 스위트를 만들고, 에이전트에게 **모든 테스트 통과를 완료 조건**으로 제시
- 구현 계획을 진행하던 중 변경이 생기면 **같은 세션을 유지**하는 것을 권장:
  - 에이전트가 기존 기록을 이용해 사용자가 임의로 정한 변수명을 실제 코드에 맞출 수 있음
  - 변경을 적용한 뒤 원래 구현 계획으로 혼선 없이 돌아갈 수 있음

> 주의: 기능을 하나씩 즉흥적으로 고치는 방식은 회귀 버그를 반복해서 만들 수 있으니, 고친 내용을 테스트로 고정해 이후 수정에서 깨지지 않게 해야 함
