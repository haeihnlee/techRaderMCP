## 🔑 핵심 요약
- 'Build It' 시리즈 1화로, 코딩 없이 **Gemini 웹 앱 → Google Stitch → AI Studio** 순서로 AI 개인 트레이너 앱을 프로토타이핑하는 과정을 시연
- 채팅만으로 만든 에이전트는 **상태 관리(요일·이전 운동 기억)** 와 **사용성**에 한계가 있음 → 창의적 AI 부분과 기존 트래킹 앱 부분을 나누는 **관심사의 분리**가 핵심
- 디자인 반복 작업은 토큰 소모가 큰 AI Studio 대신 **Stitch에서 먼저** 하고, 확정된 뷰 이미지와 Gemini가 만든 프롬프트로 AI Studio에서 빌드

## 📣 주요 발표 내용
- **Gemini 웹 앱 = 가장 쉬운 에이전트**: 채팅만으로 맞춤형 운동 계획 생성·수정 (덤벨 추가, 러닝 병행, 소프트볼 일정 고려 등)
- **채팅형 에이전트의 문제점**
  - 오늘 요일·어제 한 운동을 잊고 시간 계산을 헷갈림
  - 한 번 말한 조건(예: "내일 더블헤더 경기")을 이후 모든 계획에 계속 적용
  - 운동 중 흐름이 끊기는 UX
- **Gemini를 사고 파트너로 활용**: 바로 앱을 만들게 하지 않고 먼저 문제를 분석하게 함 → "채팅 UI는 창의적 생성엔 좋지만 **작업 실행·안정적 상태 관리·실시간 추적**엔 근본적 결함이 있다"는 결론
- **Google Stitch**로 UI 설계
  - Gemini가 써 준 Stitch용 프롬프트로 채팅 뷰 + 트래커 뷰를 생성
  - 피드백 반복: 불필요한 카드·`시작` 버튼 제거, 시간 정보를 헤더로 이동, **슈퍼세트** 구조 반영, 운동별 정보(ℹ️) 버튼과 상세 뷰 추가
  - 최종 뷰 3개를 이미지로 Gemini 채팅에 다시 넣고 **AI Studio용 빌드 프롬프트** 생성
- **AI Studio**에서 앱 빌드 및 수정
  - 편집 도구로 레이아웃 조정 (배지·시간·근육 부위를 한 줄로 배치)
  - 운동 라이브러리 탭 → **주간 일정 탭**으로 교체 (클릭하면 운동 미리보기, 뒤로 가면 주간 뷰)
  - 코치 탭을 채팅 전용으로 바꾸고, 하단 고정 **`수정` 버튼** 추가 → 누르면 코치 탭으로 이동하며 현재 운동·주 **컨텍스트가 칩(X 표시)으로 프롬프트에 자동 첨부**
  - 하단 내비게이션 개편: `운동` → `주(Week)` 로 이름 변경, 가운데 원형 **`오늘`** 버튼 추가 (현재 날짜 운동 로드)
  - 오늘 화면에는 **현재 세트만** 표시하고 슈퍼세트 전환 자동 처리, 나머지 운동은 아래에 나열
- 음성 입력으로 긴 요구사항을 전달하는 방식도 시연

## 💡 개발자 포인트
- **에이전트는 목표 지향적**이라 "앱 만들어줘"라고 하면 바로 구현부터 함 → 기획·설계 단계에서는 일부러 속도를 늦추고 AI를 사고 파트너로 쓰기
- AI 앱 설계의 핵심은 **AI를 어디에 두고 어디엔 두지 않을지** 정하는 것: 창의적 추론(코치 채팅) vs 결정적인 상태·추적(일정·세트 진행)
> 스크린샷 하나만 AI Studio에 넣고 "앱 만들어줘"라고 하면 설계 결정을 에이전트가 대신 내리게 됨 — 뷰 구조는 미리 정해 두기
- 디자인 반복은 **Stitch처럼 코드를 만들지 않는 도구**에서 하는 편이 저렴함 (AI Studio는 매번 빌드·실행·검증하느라 토큰을 많이 씀)
- **컨텍스트 첨부 패턴**: UI 버튼으로 현재 화면 상태를 에이전트 프롬프트에 자동으로 붙이면, 사용자가 대상을 일일이 설명하지 않아도 정확하게 수정할 수 있음
- 도구 체인 정리: `Gemini 웹 앱`(기획·프롬프트 작성) → `Google Stitch`(UI 디자인) → `AI Studio`(빌드·편집) — 같은 맥락에서 `Google Antigravity`도 언급됨
- 다음 화에서 제품 정의를 더 깊게 다듬어 앱을 고도화할 예정
