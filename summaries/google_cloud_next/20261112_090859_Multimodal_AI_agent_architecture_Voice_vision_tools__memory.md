## 🔑 핵심 요약
- **양방향 실시간 멀티모달 에이전트**(Omni 앱) 시즌 1을 정리하는 회고 에피소드로, 음성·ADK·도구·브라우저 제어·기억·시각 6개 에피소드를 하나의 아키텍처로 묶어 설명
- 설계는 두 가지 질문으로 정리됨: **연속(stream)인가, 완성형(single)인가** / **대화를 차단(blocking)하는가, 하지 않는가**
- 유용한 멀티모달 에이전트는 기능을 모아 놓은 것이 아니라 **경계를 나눈 것** — 라이브 경로와 백그라운드, DB와 시맨틱 메모리, 스냅샷과 스트림 사이의 경계를 제대로 나누는 것이 핵심

## 📣 주요 발표 내용
- **Omni 앱 루프**: 인식(Perceive) → 추론(Reason) → 표현(Express). 입력을 받아 생각하고, 필요한 감각으로 응답
- **양방향(Bidirectional)**: 에이전트가 듣는 중에도 말할 수 있고, 세션이 열려 있는 동안 카메라 프레임과 도구 호출이 계속 오감
- 시즌 1 에피소드 구성:

| 에피소드 | 주제 | 핵심 내용 |
|---|---|---|
| 1 | 음성 | 텍스트에서 실시간 양방향 음성으로 전환, 마이크 상시 스트리밍, **끼어들기(barge-in)** 지원 |
| 2 | ADK | 원본 실시간 루프 위에 구조를 얹음 — **Agent**가 결정하고 **Runner**가 실행하며 **Session**이 상태를 유지 |
| 3 | 도구 | 음악 재생·건너뛰기·일시정지 등. 모델이 결정하고 코드가 실행 |
| 4 | 브라우저 제어 | 실제 Chrome 창에서 클릭·타이핑, 픽셀 좌표로 행동하고 다음 스크린샷으로 결과 확인 |
| 5 | 기억 | 사실은 **구조화 데이터**에, 이해(의미)는 **벡터/시맨틱 메모리**에 저장. 장기 기억은 실시간 경로 밖에서 처리 |
| 6 | 시각 | 라이브 비디오는 MP4가 아니라 **시간에 따라 보내는 이미지 프레임**의 연속 |

- **시즌 2 예고**: 인지 쪽은 이미지·문서·긴 오디오/비디오 이해와 **여러 에이전트의 동시 인지**, 표현 쪽은 이미지 생성·편집, 모션 생성, 비디오 연출

## 💡 개발자 포인트
- **입력 유형에 따라 전송 방식 결정**
  - 연속 입력(마이크, 라이브 카메라)은 **스트림**으로 보냄
  - 완성형 입력(브라우저 스크린샷, 제품 사진, 텍스트 지시)은 **한 번에 보냄**
  - 살펴보기만 하면 되는 경우는 **스냅샷**, 계속 지켜봐야 하는 경우는 **프레임 스트림**
- **느린 작업은 핫 패스에서 빼기**
  - 페이지 로드, 오래 걸리는 도구 작업, 메모리 추출, 생성 작업 등은 비동기로 따로 실행
  - 결과는 다음 이벤트·스냅샷·메모리 읽기로 다시 가져옴

> ⚠️ 실시간 도구의 규칙: **도구가 느려도 침묵이 흐르게 두지 말 것.** 라이브 루프는 지연을 허용하지 않음

- **메모리 이원화**: 정확해야 하는 사실(예: 사용자 설정, 수치)은 구조화 DB에, 맥락과 의미는 벡터 스토어에 저장
- 코드 경로는 raw Live API를 쓰는지, **ADK**를 쓰는지, 자체 래퍼를 쓰는지에 따라 달라지지만 **설계 판단 기준은 같음**
- ADK를 쓰면 개발자는 **에이전트 정의**만 하고 실시간 루프 실행은 ADK가 맡음
