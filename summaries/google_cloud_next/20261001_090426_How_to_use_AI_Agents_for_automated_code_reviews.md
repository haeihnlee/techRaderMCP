## 🔑 핵심 요약
- **하니스 엔지니어링(Harness Engineering)** = 에이전트를 계속 **기준점으로 되돌리는** 기법들의 묶음
- **작은 PR**은 사람이 검토하기 쉽고, 같은 이유로 **에이전트 코드 리뷰**도 맡기기 쉬움
- PR의 상태 공간을 좁히면 사람 개입이 줄어 에이전트 루프를 **더 길고 크게** 돌릴 수 있음

> ℹ️ 추출된 자막이 짧은 발췌(쇼츠/클립 분량)라서 발표의 일부만 요약했습니다.

---

## 📣 주요 발표 내용
- **하니스 엔지니어링**: 에이전트가 목표에서 벗어나지 않게 다시 정렬시키는 기법이 점점 정교해지고 있음
- **작은 PR 전략**: 변경 범위를 좁히면 검토 상태 공간이 줄어듦
  - 사람이 리뷰하기 쉬움
  - 에이전트에게 리뷰를 맡기기도 쉬움
- **루프 확장**: 짧은 체인에서 결과를 믿을 수 있으면 작은 변경을 이어 붙여 더 긴 작업으로 확장할 수 있음
- 남은 질문: 짧은 체인의 결과를 얼마나 믿을 수 있는가? 작은 변경을 끝까지 쌓았을 때도 결과가 괜찮은가?

---

## 💡 개발자 포인트
- 에이전트 자동 리뷰를 붙이려면 먼저 **PR을 작게 쪼개는 습관**부터 들일 것
- 에이전트 루프 길이는 **짧은 체인이 얼마나 믿을 만한지**에 맞춰 단계적으로 늘릴 것
- 루프가 길어질수록 에이전트를 기준점으로 되돌리는 **하니스(검증·가드레일)** 설계가 중요해짐

> ⚠️ 짧은 체인의 신뢰성이 확인되지 않은 상태에서 루프부터 키우면 오류가 쌓일 수 있음 — "작게 검증 → 점진 확장" 순서를 지킬 것
