## 🔑 핵심 요약
- 음성→액션 에이전트 **Scribante**에 **Vertex AI Memory Bank**(장기 기억)와 **rolling window compaction**(컨텍스트 압축)을 붙여 토큰 사용량을 **80% 이상** 줄인 사례
- 채팅 히스토리를 프롬프트에 그대로 넣는 방식은 스트리밍 에이전트에서 매 턴 수만 토큰을 쓰고 지연 시간도 늘림
- Memory Bank는 엔티티 추출·중복 제거·충돌 해결·사실 갱신을 **백그라운드에서 비동기로** 자동 처리함. 지식 그래프 수준의 구조화 품질을 RAG 수준의 토큰 비용으로 얻을 수 있음

## 📣 주요 발표 내용
- **Scribante 3단계 파이프라인**
  - 1단계: **Google Cloud Speech-to-Text**로 음성을 텍스트로 변환함(AI 에이전트 없이 빠른 전사만 수행)
  - 2단계: **ADK 멀티 에이전트 파이프라인**. 두 전문 에이전트가 병렬로 동작함. 하나는 rolling summary를 만들고, 다른 하나는 캘린더 일정·작업·검색 쿼리·개발 티켓을 추출함
  - 3단계: **결정론적 date resolver**가 "다음 주 수요일 오후 3시" 같은 상대 표현을 정확한 날짜로 바꾸고, 결과를 **execution gate**로 넘김
- 파이프라인은 **읽기 전용**으로, 앱에 제안 카드만 만들고 사용자가 **Approve**를 눌러야 Google Calendar·Workspace·Jira에 실제로 반영됨
- **기존 메모리 방식 3가지와 한계**
  - **Flat prompting**: 히스토리를 그대로 붙이는 방식. 구현은 쉽지만 2초마다 tick이 도는 스트리밍 환경에서 컨텍스트가 폭발함
  - **Naive RAG(Vector DB)**: 토큰은 줄지만 **stateful synthesis**가 없음. "뉴욕에서 샌프란시스코로 이사했다"처럼 사실이 바뀌어도 두 진술을 모두 가져와 어느 쪽이 최신인지 판단하지 못함
  - **Open Knowledge Graph**: 관계 표현에는 강하지만 엔티티 추출 파이프라인, 스키마 관리, 변경 로직을 직접 만들어야 해 개발 부담이 큼
- **Vertex AI Memory Bank 데모**
  - Memory Bank를 생성하면 ID가 발급되고 GCP 콘솔에서 확인할 수 있음
  - **Ingestion**: 대화의 잡음은 버리고 사실만 저장함(예: "차보다 커피를 선호", "행사 오프사이트에서는 채식 케이터링 필요")
  - 각 엔트리에는 resource name, fact, 생성일, 수정일이 들어감
  - **Retrieval**: 한 달 뒤 다른 세션에서도 사용자 선호를 불러와 답변함
- **Rolling window compaction**: intent classifier에 최근 10줄 대신 **약 40단어**만 보냄. 40은 고정값이 아니며 문장 길이에 맞게 조정함
- **토큰 텔레메트리 대시보드**: 전사, 요약, 윈도우 각각의 토큰 수와 절감률을 실시간으로 보여줌

## 💡 개발자 포인트
- 스트리밍 에이전트는 **전체 히스토리를 넣지 말고**, 장기 사실은 Memory Bank에 두고 최근 컨텍스트만 짧은 윈도우로 보내는 구성이 효과적임
- **컴팩션의 목적**: 프롬프트 한도 초과 방지, 관련 없는 정보 제거, 지연 시간 단축, **lost in the middle** 문제 회피
- **컴팩션 방식 두 가지**
  - **Semantic summary compaction**: LLM이 요약을 만드는 방식
  - **Rule-based pruning**: 툴 호출의 중간 결과처럼 필요 없는 부분을 규칙으로 잘라내고 최종 출력만 남기는 방식
- 메모리에 이미 있는 사실(예: 좋아하는 색)은 프롬프트에 다시 넣을 필요가 없어 intent classifier 입력을 크게 줄일 수 있음
- 사실 갱신이나 충돌 해결이 필요하면 naive RAG 대신 Memory Bank처럼 **사실 단위로 관리하는 메모리**를 고려할 것
> ⚠️ 외부 시스템(캘린더, Jira 등)에 쓰기 작업을 하는 에이전트는 Scribante처럼 **read-only 제안 + 사용자 승인 게이트** 구조로 만드는 편이 안전함
- 컴팩션 효과를 검증하려면 토큰 텔레메트리 대시보드처럼 **측정 가능한 지표**를 함께 만드는 것을 권장함
