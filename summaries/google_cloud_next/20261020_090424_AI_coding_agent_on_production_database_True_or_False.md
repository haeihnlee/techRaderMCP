# AI coding agent on production database? True or False?

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=fNImL07VZMk
- **요약 일시**: 2026-10-20 09:04:24

---

## 🔑 핵심 요약
- AI 코딩 에이전트에게 **운영(production) DB 접근 권한**을 주는 것은 "절대적인 거짓", 즉 하면 안 되는 일
- 에이전트는 **샌드박스**에 격리하고 **전용 개발 DB**만 제공해야 함
- 운영 데이터 복사본을 쓴다면 반드시 **비식별화(de-identification)** 후 사용

---

## 📣 주요 발표 내용
- 단 한 번의 **환각(hallucination)**으로 운영 DB 전체가 삭제될 수 있음
- 실제 개인정보(PII)를 AI에 노출·학습시키면 **개인정보 보호 규정 위반**으로 벌금 위험
- 해결책: 에이전트 샌드박싱 + 개발 전용 DB 제공
- 운영 데이터 복사 시 실제 개인정보를 **가짜(synthetic) 데이터**로 치환

---

## 💡 개발자 포인트
> ⚠️ 지금 AI 에이전트에 부여된 운영 환경 접근 권한(DB 자격증명, 서비스 계정 등)을 즉시 회수할 것
- 에이전트 실행 환경은 운영 네트워크·자격증명과 분리된 **샌드박스**로 구성
- 에이전트용 DB는 개발/스테이징 전용 인스턴스로 분리하고 최소 권한 원칙 적용
- 운영 데이터를 시드로 사용할 때는 마스킹·토큰화 등 **비식별화 파이프라인**을 선행
- 파괴적 쿼리(`DROP`, `DELETE`, `TRUNCATE`)가 운영에 닿을 수 없는 구조를 기본으로 설계
