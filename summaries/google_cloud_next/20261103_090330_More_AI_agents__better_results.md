# More AI agents = better results?

- **출처**: https://www.youtube.com/watch?v=yDLv-bNfrSI
- **요약 일시**: 2026-11-03 09:03:30

---

## 🔑 핵심 요약
- **에이전트 수를 늘린다고 결과가 항상 좋아지지는 않음**: 무엇을 만드느냐에 따라 효과가 다름
- 대표 패턴 두 가지는 **다수결 투표(voting)**와 **역할 분담형 에이전트 팀**
- 에이전트끼리 서로의 결과물을 이어받으면 **실수가 뒤로 전파될** 위험이 있음

---

## 📣 주요 발표 내용
- **투표 방식**: 여러 에이전트가 같은 버그를 따로 고친 뒤 가장 많이 나온 답을 고름
- 다만 가장 많이 나온 답도 틀릴 수 있음
- **역할 분담 방식**: 인터페이스(UI) 담당, 데이터 처리 담당, 테스트 담당 에이전트로 나눔
- 서로 독립적인 작업은 **병렬로 실행**해 전체 시간을 줄일 수 있음
- **테스트 담당 에이전트**가 다른 에이전트들이 놓친 버그를 잡아낼 수 있음
- 에이전트 팀의 장점: 다양한 아이디어 시도, 빠른 작업, 실수 발견

---

## 💡 개발자 포인트
- 멀티 에이전트 구조는 기본값으로 두지 말고 **작업 성격에 맞춰** 고를 것
- 정답을 검증할 수 있는 작업(예: 버그 수정)에서는 투표가 쓸모 있지만, 다수결 결과를 그대로 믿지 말고 **테스트로 따로 검증**할 것
- 역할 분담 구조에서는 **독립적인 하위 작업**을 찾아 병렬로 돌리는 것이 속도를 높이는 핵심
- 검증·테스트 역할의 에이전트를 따로 두면 품질 안전장치가 됨

> ⚠️ 주의: 에이전트가 앞 단계의 결과물 위에서 작업하는 파이프라인에서는 한 에이전트의 실수가 다음 단계로 **연쇄 전파**됨 → 단계 사이에 검증 지점을 둘 것
