## 🔑 핵심 요약
- **Looker CLI**는 Ruby 기반 오픈소스 도구 **Gazer**를 **Go로 처음부터 다시 작성**한 명령줄 도구로, Looker의 **API 전체**를 다룰 수 있음
- 에이전트(Antigravity, Gemini, Claude, ChatGPT 등)가 Looker 인스턴스를 관리할 때 쓰기 좋게 설계됨. 입력과 출력이 모두 **JSON**
- MCP 서버는 도구 수가 많아질수록 컨텍스트가 커지는 한계가 있음. CLI는 컨텍스트를 미리 쓰지 않고, 에이전트가 **스킬**과 도움말 명령으로 필요할 때 사용법을 알아냄

---

## 📣 주요 발표 내용
- 핵심 기능: 대시보드와 Look을 JSON으로 내보낸 뒤 다른 인스턴스에 다시 만들기 (개발 ↔ 운영 환경 이동)
- DevOps용 기능: 사용자, 프로젝트, 데이터 소스(연결) 생성 등 인스턴스 구축과 운영
- Docker·Kubernetes·Git처럼 **하나의 명령 아래 여러 하위 명령**이 있는 구조
- `meta tree`: 모든 명령, 하위 명령, 그 아래 명령까지 트리로 출력
- `meta search <키워드>`: 키워드(예: `dashboard`)와 관련된 명령 검색
- API 명령의 **템플릿 스위치**: API 요청 본문의 빈 JSON 템플릿을 출력함. 에이전트는 처음부터 만드는 것보다 빈 템플릿을 채우는 데 훨씬 능숙함
- `health pulse`: 오픈소스 도구 **Henry**의 상태 점검 기능을 CLI에 통합함
  - 확인 항목: DB 연결, 대시보드 성능, 대시보드 오류, Explore 성능, 예약(schedule) 실패
- **Looker 스킬**을 함께 제공해 에이전트가 CLI 사용법을 익히도록 도움
- 저장소: `github.com/looker-open-source/looker-cli`. GitHub Actions에서 프로젝트 배포 → 연결 생성 → 쿼리 실행까지 통합 테스트 예시가 있음

## 💡 개발자 포인트
- **MCP와 CLI 구분해서 쓰기**
  - MCP: 비즈니스 사용자까지 쓰는 **맞춤형 도구 몇 개**에 적합. 컨텍스트 안의 MCP 도구는 **50개 이하**가 권장됨
  - CLI: 수백 개 명령이 있는 **넓은 API 전체**를 다룰 때 적합. 주로 개발자와 기술 수준이 높은 사용자용
- 에이전트용 도구 설계가 바뀜: 예전에는 15~20개 API 호출을 묶은 **상위 수준 명령**(예: 대시보드 복제)을 만들었음. 지금은 에이전트가 **세분화된 개별 단계**를 직접 조합하므로 연결 코드가 필요 없음
- 활용 예: 통합 테스트 후 남은 `test`로 시작하는 대시보드와 Look을 에이전트에게 찾아서 지우게 함. 삭제 전에 대상 분석을 받고 검토(audit)할 수 있음
- 스크립트로 자동화할 수 있어 CI/CD 파이프라인에서 Looker 인스턴스를 배포하고 테스트하기 좋음
- 직접 키보드로 작업하는 방식과 에이전트에게 권한을 주고 맡기는 방식을 쉽게 오갈 수 있음
- LookML 생성과 업데이트에도 에이전트와 함께 쓸 수 있음

> ⚠️ 에이전트에게 삭제 같은 파괴적 작업을 맡길 때는 분석 결과를 먼저 받아 대상 목록을 검토한 뒤 실행하는 것이 좋음
