# How Knowledge Catalog’s self-learning enrichment grounds enterprise AI agents

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=qeWzgLGSkls
- **요약 일시**: 2026-10-23 09:04:37

---

## 🔑 핵심 요약
- **Knowledge Catalog** 없이 `BigQuery` 에이전트는 비즈니스 정의(예: "프리미엄 고객")를 추측해, SQL은 유효해도 **틀린 답**을 낸다
- **Knowledge Studio**는 데이터 자산·문서·쿼리 이력을 **컨텍스트 그래프**로 인덱싱해 에이전트 그라운딩을 정보 검색 문제로 해결한다
- Gemini 기반 **자기학습형 보강(enrichment)** 이 대화 피드백을 지식 후보로 바꾸고, 데이터 스튜어드 승인 후 전사 에이전트에 반영된다

---

## 📣 주요 발표 내용
- **Knowledge Studio**: 데이터 스튜어드·컨텍스트 엔지니어용 관리 콘솔
- 운영 환경을 **인터랙티브 컨텍스트 그래프**로 인덱싱하고 자연어 검색 지원
- 검색 결과로 Cloud Storage 정책 문서, 검증된 `BigQuery` 테이블 관계, 보강된 컬럼 메타데이터, 실제 워크로드에서 추론한 **쿼리-답변 쌍**을 제공
- **Gemini Enterprise**에 **Knowledge Catalog 커넥터** 추가: 활성화하면 에이전트가 스키마 탐색 없이 한 번의 응답으로 정답(데모: 평균 주문액 $88)을 반환
- 통합 대상: **SAP 카탈로그**, `BigQuery`, `Spanner`, **dbt**, **Looker** 시맨틱 모델 (LookML 지표도 물리 테이블과 함께 인덱싱)
- **보강 에이전트 워크플로우**: GCS, Google Workspace, GitHub, SharePoint의 정형 스키마와 비정형 문서를 크롤링해 **관리형 컨텍스트 세트(managed context set)** 로 인덱싱
- Gemini Enterprise·BigQuery 에이전트의 **실제 상호작용 기록**에서 정의 변경을 자동으로 잡아내 구조화된 지식 후보로 변환
- 스튜어드가 AI 보강 제안을 **diff 형태**로 검토·편집·거부 (Human-in-the-loop)
- 승인된 컨텍스트는 **IAM**으로 접근이 통제되는 컨텍스트 세트에 게시되고, 연결된 모든 에이전트에 즉시 반영

---

## 💡 개발자 포인트
- Text-to-SQL 에이전트의 정확도 문제는 모델보다 **비즈니스 정의 누락**이 원인인 경우가 많으니, 시맨틱 레이어·용어집부터 정비할 것
- LookML·dbt 모델에 지표를 정의해 두면 에이전트 그라운딩 소스로 그대로 쓰인다
- 컨텍스트 엔지니어가 **자동 신뢰도 임계값**을 설정해 보강 품질을 조절할 수 있다
- 사용자 개인 메모리(Gemini의 대화 기억)와 **전사 컨텍스트 반영**은 별개이니, 정의 변경은 카탈로그 경로로 반영되게 설계할 것
> 주의: 에이전트·최종 사용자는 IAM으로 **승인된 컨텍스트만** 검색할 수 있으므로 컨텍스트 세트 권한 설계가 필요하다
- 수치는 Google **내부 벤치마크** 기준이니 도입 전 자체 데이터로 검증할 것

| 지표 | 개선 효과 (내부 벤치마크) |
| --- | --- |
| 정확도 | 약 **4배** 향상 |
| 지연 시간 | **1/3** 수준으로 단축 |
| 토큰 비용 | 최대 **75%** 절감 |
