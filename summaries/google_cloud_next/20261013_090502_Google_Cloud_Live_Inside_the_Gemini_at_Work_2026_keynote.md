# Google Cloud Live: Inside the Gemini at Work 2026 keynote

- **출처**: https://www.youtube.com/watch?v=WuqwGPtZwvY
- **요약 일시**: 2026-10-13 09:05:02

## 🔑 핵심 요약
- 가장 큰 발표는 **Gemini Agent**입니다. 업무를 돕는 **범용 상시 가동(always-on) 에이전트**로, 클라우드의 단일 두뇌 하나가 Docs·Chat·Gmail·CLI·모바일의 요청을 모두 처리합니다
- 신규 최상위 모델 **Gemini Argon**(자막 표기 기준)이 공개됐습니다. **100만 토큰 출력 창**을 지원하며 장기 SW 엔지니어링 작업과 **취약점 자율 탐색·검증·패치**에 특화돼 있습니다
- 데이터는 **Knowledge Catalog + Smart Storage**, 거버넌스는 **에이전트 고유 ID + Smart Routing(토큰 지출 한도)**으로 다룹니다. 규제 산업의 프로덕션 도입 병목을 겨냥한 구성입니다

---

## 📣 주요 발표 내용
- **Gemini Agent: 단일 에이전트 아키텍처**
  - 상태를 저장하지 않는(stateless) 채팅 앱 방식에서 벗어나, **클라우드에서 계속 실행되는 하나의 에이전트**를 씁니다
  - Google Docs·모바일·명령줄 등 어디서 보낸 요청이든 **동일한 에이전트**로 가서 **하나의 실행 기록**에 쌓입니다
  - 예시 흐름: PM이 Docs에 출시 계획 작성 → Chat에서 요약 → Gmail로 외부 업체 승인 스레드 자동 생성 → **`Antigravity CLI`**로 "마이크로사이트 구축 + 기술 문서 업데이트" 지시 → 엔지니어 없이 사이트 생성·배포까지 진행
- **Dream Mode (비동기식 성찰 파이프라인)**
  - 작업이 끝나면 별도 프로세스가 세션을 되돌아보고 **메모리·선호도·글쓰기 스타일**을 추출해 다음 작업에 반영합니다
- **클라이언트와 실행 환경 분리 (persistent cloud actor)**
  - 실행 런타임이 클라이언트와 무관하게 돌아가므로 노트북을 닫거나 연결이 끊겨도 작업이 계속됩니다
  - **GWS·Microsoft·Slack** 어디서든 접근할 수 있고, 예약 루틴을 백그라운드로 돌릴 수 있습니다
  - 단계별 워크플로를 직접 짜지 않아도 Gemini가 자연어 지시만으로 필요한 **서브에이전트를 스스로 구성**합니다
- **비동기 휴먼 인 더 루프(human-in-the-loop)**
  - 권한 승인이 필요하면 **휴대폰 푸시 알림**이 오고, 모바일에서 검토·승인하면 백그라운드 작업이 이어집니다
  - Workspace 댓글에서 에이전트를 **태그**해 동료에게 부탁하듯 작업을 맡길 수 있습니다
- **엔터프라이즈 통합**
  - **Google Workspace·ServiceNow·Salesforce·Slack**을 하나의 에이전트가 연결합니다
  - 예: 240문항짜리 RFP 작성처럼 여러 팀에서 자료를 모아야 하는 업무를 자동화합니다
- **Knowledge Catalog**
  - 데이터를 **재색인하지 않고** 비즈니스 데이터 정의·지표·규칙을 매핑하는 **통합 맥락 레이어**입니다
- **Smart Storage**
  - 비정형 PDF·스캔본·미디어 같은 **"다크 데이터"**를 저장된 위치에서 바로 식별·분류해 Knowledge Catalog에 매핑합니다
  - 기존의 깨지기 쉬운 ETL 색인 파이프라인을 대체하는 것이 목표입니다
- **거버넌스 / 보안**
  - 각 에이전트가 **암호화로 인증된 고유 ID**와 자체 제한을 갖습니다. 감사 로그에 사용자 대신 에이전트 단위로 기록됩니다
  - 조직이 설정한 정책·가드레일을 그대로 **상속**하고, 에이전트 작업은 모두 추적할 수 있습니다
  - 앞서 언급된 **Agent Gateway**와 함께 동작합니다
- **Smart Routing**
  - **실시간 지출 한도**를 세부 단위로 설정할 수 있습니다
  - 하위 작업마다 처리 가능한 **가장 빠르고 효율적인 모델로 자동 라우팅**해, 최상위 모델에 가까운 품질을 더 낮은 비용으로 얻습니다

## 💡 개발자 포인트
- 에이전트 개발의 기본 형태가 **"로컬 세션에 묶인 스크립트" → "클라우드에서 계속 실행되는 백그라운드 팀원"**으로 바뀌고 있습니다
  - 리포 리팩토링·대규모 마이그레이션처럼 오래 걸리는 작업이 연결 끊김으로 날아가는 문제를 해결하는 데 초점이 있습니다
- **`Antigravity CLI`**로 터미널에서도 Docs·Chat과 맥락을 공유하는 같은 에이전트를 호출합니다. 긴 프롬프트나 기획서 첨부가 필요 없다는 점이 강조됐습니다
- **Intent-driven engineering**: SQL이나 ML 세부 지식 없이 원하는 결과만 말하면 에이전트가 처리합니다. 데이터 엔지니어가 만든 모델의 맥락이 마케터의 질문까지 이어집니다

> ⚠️ **권한·감사 모델 변화**: 지금까지 에이전트는 사용자 자격 증명으로 동작해 감사 로그에 사용자 이름만 남았습니다. 이제 에이전트별 **고유 ID**로 권한과 책임이 분리됩니다. 사용자 토큰을 넘겨주던 기존 통합 방식은 재검토가 필요합니다

> 💸 **토큰 비용 관리**: 토큰 최적화는 프로젝트 초반에 놓치기 쉽지만 나중에 가장 문제가 되는 영역입니다. 에이전트를 도입할 때 **Smart Routing 지출 한도**를 처음부터 함께 설계하는 것이 좋습니다

- 규제 산업(금융·법률)에서 병목은 도입이 아니라 **프로덕션 승인 단계**에 있다고 진단했습니다. 컴플라이언스 팀을 설득하려면 거버넌스·추적성·게이트웨이 구성이 핵심입니다
