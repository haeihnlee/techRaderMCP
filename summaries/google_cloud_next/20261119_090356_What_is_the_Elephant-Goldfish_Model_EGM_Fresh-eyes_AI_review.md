# What is the Elephant-Goldfish Model (EGM)? Fresh-eyes AI review for specs and code

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=6P1polyfAqM
- **요약 일시**: 2026-11-19 09:03:56

---

## 🔑 핵심 요약
- **Elephant-Goldfish Model(EGM)** 은 Google이 오픈소스로 공개한 AI 에이전트 기반 사양(spec)·코드 리뷰 방법론
- **코끼리(Elephant)** 에이전트는 프로젝트 전체 맥락을 기억하며 사양 초안을 작성하고, **금붕어(Goldfish)** 리뷰어는 이전 대화 없이 새로운 맥락으로 검토
- 맥락을 많이 알수록 스스로의 **암묵적 가정**을 알아차리지 못한다는 문제를 역할 분리로 해결

---

## 📣 주요 발표 내용
- 코딩 에이전트는 요구사항·결정사항·과거 대화까지 모두 기억하지만, 이것이 오히려 **가정의 맹점**을 만든다는 문제 제기
- **Elephant**: 전체 프로젝트 컨텍스트를 유지하며 섹션별로 사양 초안 작성
- **Goldfish**: fresh context로 시작, 오직 **초안과 그 소스만** 읽고 명시되지 않은 가정과 위험을 포착
- 3단계 워크플로우
  - 1) 아이디어 브레인스토밍
  - 2) 섹션별 사양 초안 작성
  - 3) 새로운 시각(fresh eyes)으로 검토
- 리뷰 결과를 해결하고 설계가 탄탄해질 때까지 **반복(iterate)**
- Google 제공 **오픈소스**로 공개

---

## 💡 개발자 포인트
- 장기 세션 에이전트에게 셀프 리뷰를 시키는 대신, **컨텍스트를 비운 별도 서브에이전트**로 리뷰를 수행하는 패턴을 적용 가능
- 금붕어 리뷰어에게는 대화 히스토리가 아닌 **산출물(spec/code)과 원본 소스만** 전달하는 것이 핵심
- 사양 문서는 **섹션 단위**로 작성·검토해야 리뷰 범위가 명확해짐
- 트레이드오프 평가와 최종 구축 결정은 여전히 **사람(개발자)의 몫**

> 주의: 리뷰어에게 이전 맥락을 섞어 넘기면 "fresh eyes" 효과가 사라지므로 컨텍스트 격리를 유지해야 함
