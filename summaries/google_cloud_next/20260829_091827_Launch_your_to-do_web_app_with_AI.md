# Launch your to-do web app with AI

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=kSiWL6Z38Z0
- **요약 일시**: 2026-08-29 09:18:27

---

## 🔑 핵심 요약
- **Google AI Studio Build mode**를 활용해 협업형 할 일 관리 웹 앱을 빠르게 생성하고 배포한다.
- `Firestore`를 데이터베이스로 사용해 작업 목록을 저장하며, 여러 화면에 변경사항을 실시간 동기화한다.
- `Firebase Auth`의 Google 로그인을 연결해 사용자 인증을 추가하고, 앱을 `Cloud Run` 기반으로 공개 배포한다.

---

## 📣 주요 발표 내용
- 정적 포트폴리오 사이트와 달리 작업 목록처럼 지속적으로 변경되는 데이터에는 백엔드와 데이터베이스가 필요하다.
- AI Studio에 “Firebase를 백엔드로 사용하는 협업형 할 일 목록 앱”을 프롬프트로 입력하면 애플리케이션 골격을 생성할 수 있다.
- 생성 과정에서 `Enable Firebase Firestore`를 승인하면 작업 데이터 저장소가 구성된다.
- `Firebase Auth`와 Google 로그인을 통해 사용자 로그인 기능을 짧은 시간 안에 추가할 수 있다.
- `Publish`의 `get started and publish your app` 절차를 통해 vanity domain으로 앱을 배포한다.
- 배포된 애플리케이션은 전 세계 사용자가 접근할 수 있으며, Firebase Console에서 코드와 저장된 작업 데이터를 확인할 수 있다.
- Firestore의 **real-time sync**로 한 화면에서 추가·수정한 작업이 개발 버전과 배포 버전의 다른 화면에도 자동 반영된다.
- 개발 중 오류가 발생하면 AI Studio가 자동 수정을 시도할 수 있으며, 배포 후 Firebase Console에서 데이터를 직접 점검할 수 있다.

---

## 💡 개발자 포인트
- `Firestore`는 데이터 저장뿐 아니라 실시간 동기화까지 제공하므로, 협업 앱의 상태 전파 로직을 직접 구현하는 부담을 줄인다.
- 데이터베이스를 연결하는 앱은 사용자 식별과 권한 검사가 필수다. `Firebase Auth`를 함께 구성해 누가 데이터를 읽고 수정할 수 있는지 관리해야 한다.
- 프론트엔드·백엔드·데이터베이스로 구성된 풀스택 구조를 이해하면 AI가 생성한 앱의 각 부분을 검토하고 확장하기 쉽다.
- Firebase Console에서 데이터를 직접 수정하면 연결된 앱 화면에 변경이 전달되므로, 운영 데이터 변경 시 권한과 검증 절차를 마련해야 한다.
> 주의: 데모처럼 데이터베이스에 제한적인 보안 규칙만 둔 상태로 공개 배포하면 누구나 임의 데이터를 추가하거나 수정할 수 있다. 실제 서비스에서는 Firestore 보안 규칙과 사용자별 권한을 반드시 설정해야 한다.
- 실험용 앱은 사용이 끝난 뒤 `Unpublish app`으로 공개 배포를 제거해 외부 사용자의 접근과 임의 데이터 입력을 차단한다.
