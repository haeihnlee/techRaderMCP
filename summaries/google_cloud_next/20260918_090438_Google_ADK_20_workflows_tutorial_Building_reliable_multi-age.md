## 🔑 핵심 요약
- **ADK 2.0**은 `sequential`, `parallel`, `loop` 세 가지 네이티브 워크플로우 프리미티브를 제공하여 에이전트 조정을 **프롬프트가 아닌 코드**로 처리
- 에이전트에 워크플로우 지시사항을 프롬프트에 넣는 방식보다 **결정론적 코드**로 조정하는 것이 훨씬 신뢰성이 높음
- 루프에는 반드시 **최대 반복 횟수 제한**을 설정해야 과도한 클라우드 비용 방지 가능

## 📣 주요 발표 내용
- **ADK 2.0 워크플로우 프리미티브** 3종 제공:
  - `SequentialAgent` — 에이전트를 순차적으로 실행
  - `ParallelAgent` — 여러 에이전트를 동시에 실행
  - `LoopAgent` — 조건이 충족될 때까지 에이전트를 반복 실행
- **함수 노드(Function Node)**: 일반 Python 코드를 워크플로우에 삽입 가능 (루프 게이트, 데이터 청킹 등)
- 루프 종료 조건은 별도 `check_need_refinement` 함수로 정의 — 조건 충족 또는 최대 반복 횟수 도달 시 종료
- 워크플로우 그래프의 루트는 `workflow` 타입 객체로 선언하여 전체 실행 흐름을 명시적으로 구조화

## 💡 개발자 포인트
- **프롬프트로 에이전트를 조정하지 말 것**: 에이전트들이 서로 충돌하는 프롬프트를 가질 수 있고, 예측 불가능하게 동작할 위험이 있음

> **Breaking Change 아님, 권장 패턴 변경**: ADK 2.0 이전에는 에이전트 프롬프트에 "다음에 어떤 에이전트를 실행할지" 지시문을 넣는 방식이 일반적이었으나, 이제는 코드로 명시적 구조화를 권장

- **병렬 실행으로 토큰 한도 우회**: 각 에이전트가 독립적인 컨텍스트를 가지므로 토큰 한도에 덜 민감해짐
- **대용량 데이터 처리**: 출력이 토큰 한도를 초과할 경우 함수 노드로 데이터를 청크로 분할하고 `LoopAgent`로 처리
- **루프 최대 횟수 설정 필수**:
  ```python
  # 컨텍스트 변수로 시도 횟수 추적
  if context["refine_attempts"] >= 3:
      return False  # 루프 종료
  ```
- 에이전트는 한 가지 역할에만 집중하도록 설계할 것 (단일 책임 원칙 적용)
- 구조적 프로그래밍 정리(1966)의 세 구조(`sequence`, `selection`, `iteration`)를 AI 에이전트 조정에 그대로 적용하는 패러다임
