# Don't let your AI agent touch Google Calendar directly

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=pnaERetXD9c
- **요약 일시**: 2026-11-20 09:04:49

---

## 🔑 핵심 요약
- 음성 메모 앱 **Scribe**는 음성 입력을 일정·할 일로 바꿔 주며, AI 에이전트가 Google Calendar에 **직접 쓰지 못하게** 설계함
- 처리는 **3단계**: 받아쓰기 → 멀티 에이전트로 추출·해석 → **실행 게이트**(사용자 승인)
- 세션 하나에서는 잘 동작했지만, **며칠에 걸친 실제 사용**에 적용하자 구조가 무너졌다는 문제 제기로 영상이 끝남

---

## 📣 주요 발표 내용
- **1단계 – 받아쓰기**: `Google Cloud Speech-to-Text`로 음성을 텍스트로 변환함. 이 단계에는 AI 에이전트를 쓰지 않음
- **2단계 – 멀티 에이전트 파이프라인**: 전문 에이전트 2개가 병렬로 실행됨
- 에이전트 A: 대화가 진행되는 동안 **연속 요약**을 작성
- 에이전트 B: **실행 항목** 추출 (캘린더 이벤트, 할 일, 검색 쿼리, 개발 티켓)
- **결정론적 날짜 해석기**: "다음 주 수요일 오후 3시" 같은 상대 표현을 LLM 대신 규칙 기반 코드로 정확한 날짜로 바꿈
- **3단계 – 실행 게이트**: 앱 안에 **제안 카드**만 만듦. 사용자가 승인을 누르기 전에는 Google Calendar나 개발 워크스페이스에 아무것도 반영되지 않음

> ⚠️ 이 3단계 구조는 **세션 하나에서만** 검증됐음. 여러 날에 걸친 맥락(장기 상태)에서는 깨진다고 발표자가 직접 밝힘

---

## 💡 개발자 포인트
- 에이전트가 외부 시스템(캘린더, 이슈 트래커)에 **직접 쓰는 권한을 갖지 않게** 설계함. 파이프라인 전체를 **읽기 전용**으로 두고, 쓰기는 사용자 승인 이후에만 일어남 (human-in-the-loop)
- 날짜 계산처럼 정확성이 중요한 부분은 LLM 대신 **결정론적 코드**로 처리해 환각과 오차를 줄임
- 단순 변환(STT)에는 에이전트를 붙이지 않음. 에이전트는 꼭 필요한 단계에만 둠
- 요약과 실행 항목 추출을 **전문 에이전트로 나눠 병렬 실행**하면 역할이 명확해지고 지연 시간도 줄어듦
- 하루 이상 이어지는 사용 환경이라면 **세션 간 메모리와 상태 관리**를 따로 설계해야 함

> ℹ️ 자막에 "8만 개의 다중 에이전트 파이프라인"이라는 구간이 있는데, 음성 인식 오류로 보입니다(예: `ADK`). 원문으로 확인이 필요합니다
