# Web AI at the Edge: Local Vector Search, Gemma 4, & hybrid cloud routing

## 🔑 핵심 요약
- **Web AI**는 `WebGPU`·`WebAssembly`·`WebNN`으로 브라우저 클라이언트 쪽에서 ML 모델을 실행하는 기술로, **최대 310억(31B) 파라미터 Gemma 4**까지 로컬에서 빠르게 돌린 사례가 소개됨
- `vector search.js` + **EmbeddingGemma** + Gemma 4를 묶으면 **브라우저 안에서 RAG 전체**를 구현할 수 있음 (오프라인 동작, 데이터 외부 유출 없음, 토큰 비용 없음)
- 실무 권장안은 **하이브리드 라우팅**: 기기 벤치마크 결과와 모델 다운로드 상태를 보고 로컬 모델과 클라우드(Gemini)를 오가는 방식

---

## 📣 주요 발표 내용
- **`vector search.js`** (Jason 개발): EmbeddingGemma로 시맨틱 임베딩을 만들어 GPU에서 도는 로컬 벡터 DB를 구성, **텍스트 문단 10만 개를 약 100ms**에 검색
- 벡터 검색은 쿼리 문자열과 DB 안 모든 문자열 사이의 **코사인 유사도** 계산이 기본이고, 여기에 로컬 Gemma 4를 붙이면 클라이언트 전용 RAG가 됨
- **`WebNN`** (W3C Web Neural Network API): **NPU** 접근을 제공하며, 현재 일부 Google 제품에서 프리뷰 중이고 곧 정식 출시 예정
- **LiteRT 런타임** 두 가지
  - `LiteRT.js`: 임베딩 모델 같은 일반 ML 모델용
  - `LiteRT-LM.js`: LLM용이며 현재 **Gemma 제품군 중심**으로 지원 (다른 모델은 추후 확대 예정)
  - 지원되는 연산에 맞춰 실행 백엔드(`WebAssembly`, `WebGPU` 등)에 작업을 자동으로 나눠 맡겨 추론 속도를 최적화함
- `LiteRT-LM.js`는 일반 JS 라이브러리처럼 **CDN으로 import**하며, **20줄 미만의 JS 코드**로 Gemma 모델을 로드·설정·실행할 수 있음 (CodePen 예제는 영상 설명란에 공유)
- **Cross-Origin Storage (COS)** 표준 제안: 대용량 모델 파일의 **해시**로 도메인 간 캐시를 공유해, 같은 모델을 도메인마다 따로 다운로드하던 중복을 없앰

## 💡 개발자 포인트
- **Graceful degradation(우아한 성능 저하)**: 온라인일 때는 클라우드 Gemini를 쓰고, 오프라인(터널·기내 등)일 때는 미리 로드해 둔 로컬 Gemma 4로 전환해 앱이 멈추지 않게 함
  - 예: 펫샵에서 이전에 조회한 상품을 로컬 벡터 스토어에 캐싱 → 오프라인에서도 추천받고 장바구니에 담은 뒤, 다시 연결되면 동기화·결제
- **Progressive enhancement(점진적 향상)**: 가용 **VRAM**에 따라 기능을 넓힘
  - 저사양 기기: 텍스트 전용 모델로 "강아지 목줄" 같은 텍스트 검색
  - 고사양 기기: 멀티모달 모델로 사진 기반 유사 상품 검색 (예: "금색 방울이 달린 파란 고양이 목걸이")
- **하이브리드 라우팅 구현 순서**
  - 먼저 행렬 곱셈 같은 **간단한 벤치마크**로 기기가 쓸 만한 속도를 내는지 판단 → 통과하지 못하면 클라우드에 위임
  - 통과해도 **모델을 다운로드하는 동안에는 클라우드**로 UX를 유지하고, 다운로드가 끝나면 로컬 모델로 전환
  - 다운로드가 끝난 뒤 "개인정보 보호 모드" 토글을 보여 주고, 단순 작업은 로컬·복잡한 작업은 클라우드로 나누는 방식도 가능
- **소형 모델 품질 높이기**: 파인튜닝이나 큰 모델에서의 **지식 증류(distillation)**로, 특정 작업에서는 큰 모델과 비슷하거나 더 나은 성능을 낼 수 있음
  - 절차: 베이스 아키텍처(Gemma 4) 선택 → 목표 크기 결정(예: 26B MoE, 활성 4B) → 기본 성능 테스트로 엣지 케이스 찾기 → 수천 건 규모 데이터 수집 → Python 환경(Google Cloud 등)에서 재학습 → `LiteRT-LM.js` 형식으로 변환해 브라우저 배포
- 클라우드 환경과 달리 브라우저는 **로드된 뒤에야 가용 리소스를 알 수 있음** (워치·TV·폰·노트북 등 기기 편차가 큼)
- **클라우드를 써야 하는 경우**: **100만 토큰 컨텍스트**처럼 긴 입력, 또는 **수조 파라미터급 프런티어 모델**이 필요한 작업

> ⚠️ 주의: 브라우저 환경은 실행 전에 하드웨어 사양을 보장할 수 없으므로, 로컬 모델만 쓰는 설계는 피하고 반드시 클라우드 폴백 경로를 함께 설계해야 합니다.

> ⚠️ 주의: 모델 다운로드 용량이 크므로(GB 단위) 첫 실행 UX를 고려해야 합니다. COS 표준이 정착하기 전까지는 도메인마다 따로 다운로드될 수 있습니다.

> ⚠️ 주의: JS 생태계는 Python보다 AI 라이브러리·프레임워크(에이전트 오케스트레이션 등)가 부족합니다. 비전문가 개발자가 가장 많이 겪는 마찰 지점으로 언급됐습니다.

## 📅 버전 / 출시 일정

| 모델 / 기술 | 사양·상태 | 용도 / 비고 |
| --- | --- | --- |
| Gemma 4 2B | 오디오·이미지·텍스트 멀티모달 | IoT(라즈베리 파이), 저사양·구형 폰 |
| Gemma 4 4B | 멀티모달(오디오 포함), VRAM 약 **4.5GB** | 중급형 폰, 빠른 실행 |
| Gemma 4 12B | 이미지·텍스트 (오디오 미지원) | 중간 지점의 균형형 모델이지만 코딩 등에는 부족할 수 있음 |
| Gemma 4 26B MoE | 전체 26B / **활성 4B** | 4B급 속도에 대형 모델 수준의 지식 |
| Gemma 4 31B | 현재 Gemma 4 최대 모델 | 발표자는 "몇 년 전 Sonnet 3.5 수준"이라고 언급 |
| `vector search.js` | 10만 문단 검색 약 **100ms** | 로컬 벡터 DB (EmbeddingGemma) |
| `WebNN` | 일부 Google 제품에서 프리뷰 | 곧 정식 출시 예정 |
| Cross-Origin Storage | 표준 제안 단계 | 해시 기반으로 도메인 간 모델 캐시 공유 |
