# Why 5 tools beat 25 tools for AI agents

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=Nr9UvsyC7V4
- **요약 일시**: 2026-11-13 09:04:26

---

## 🔑 핵심 요약
- AI 에이전트에 도구를 **5개** 주면 잘 동작하지만, **25개**를 주면 엉뚱한 API를 호출하기 시작함
- 도구가 늘수록 설명이 모호해지고 매개변수 스키마가 겹쳐 에이전트가 헷갈림 → **"Less is more"**
- 도구가 아주 많을 때는 **점진적 공개(Progressive Disclosure)**와 런타임 **도구 레지스트리/검색**으로 해결

---

## 📣 주요 발표 내용
- 도구 수가 늘면 도구 설명(description)끼리 구분이 흐려지고 매개변수 스키마가 서로 겹쳐 **도구 선택 정확도가 떨어짐**
- **점진적 공개(Progressive Disclosure)**: 처음부터 모든 정보를 주지 않고, 힌트를 주어 에이전트가 필요할 때 한 번 더 판단하고 세부 정보를 펼쳐 보게 하는 기법
- 점진적 공개를 쓰면 더 많은 도구를 붙일 수 있지만, 일정 수준을 넘으면 **컨텍스트 윈도우** 한계와 에이전트 주의 분산 문제가 다시 생김
- 그래서 넓은 도구 카테고리 안에서 **검색하는 메커니즘**이 필요함
- 런타임에 쓸 만한 도구를 찾을 수 있도록 레지스트리를 제공하는 시스템으로 **ARD**, **AI 카탈로그**가 언급됨 (ARD는 자동 자막 표기 그대로 옮긴 것)

> ⚠️ 원본은 퀴즈 형식의 짧은 영상(Shorts)이라 자막 분량이 매우 적음. 구체적인 제품명, API, 수치는 발표에 나오지 않았음

---

## 💡 개발자 포인트
- 에이전트나 MCP 서버를 설계할 때 한 번에 노출하는 도구 수를 **작게** 유지할 것 (대략 5개 안팎이 기준)
- 도구마다 `description`을 서로 확실히 구분되게 쓰고, 비슷한 매개변수 스키마를 가진 도구는 합치거나 정리할 것
- 도구가 많아지면 **상위 카테고리 도구 → 세부 도구** 순으로 펼쳐 보이는 점진적 공개 구조를 고려할 것
- 규모가 더 커지면 모든 도구를 컨텍스트에 넣지 말고, **도구 검색/레지스트리**로 런타임에 필요한 것만 불러오도록 설계할 것
