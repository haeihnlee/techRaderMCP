# Stop your AI agent from committing secrets

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=VzpbeVdS_ok
- **요약 일시**: 2026-10-30 09:04:56

---

## 🔑 핵심 요약
- AI 코딩 에이전트가 **API 키 등 시크릿을 커밋**하지 못하도록 **pre-tool-use hook**으로 `git commit`/`git push` 전에 보안 검사 스크립트를 강제 실행하는 방법을 다룸
- 차단 시 단순 거부보다 **거부 사유를 에이전트에게 피드백**해 스스로 수정(환경 변수·**Google Cloud Secret Manager** 사용)하게 하는 방식을 권장
- 문제를 매번 고치는 대신 에이전트의 **스킬(skills)을 개선**해 재발을 막고, Google 보안 엔지니어들이 오픈소스로 공개한 리뷰 스킬 **Mantis**를 소개

---

## 📣 주요 발표 내용
- **pre-tool-use hook**: 에이전트가 Git 커밋·푸시 도구를 호출하기 전에 특정 스크립트(시크릿 스캔 등)를 실행하도록 강제
- 훅이 문제를 발견하면 두 가지 대응 가능: **커밋 자체를 하드 차단** vs **거부 사유를 에이전트에 전달해 수정 유도** (보안 사례에서는 후자 선호)
- 하드코딩된 API 키 탐지 시 해결책: **환경 변수**로 이동하거나 **Google Cloud Secret Manager**에서 로드하도록 수정
- Secret Manager의 이점은 암호화뿐 아니라 **중앙 집중식 키 교체(rotation)** 와 **접근 권한 관리**
- "방어적 개발자(defensive developer)" 스킬에 API 키 로드·Secret Manager 사용 등 **모범 사례를 추가**해, 이후 프롬프트에서 TDD(실패 테스트 → 통과) + **결정론적 보안 스캐너 + 에이전트 기반 스캐너**를 모두 통과
- Google 실제 보안 엔지니어들의 리뷰 스킬을 오픈소스로 공개: **Mantis**
- 데모에 사용된 모든 스킬과 훅이 담긴 저장소 제공 (영상 설명란 링크)

## 💡 개발자 포인트
- 시크릿은 한 번 커밋되면 **Git 히스토리에 영구히 남음** → 저장소에 들어가기 전에 막는 것이 최선
> ⚠️ 실수는 사람이 아니라 **시스템의 문제**로 보고, 실수해도 자동으로 잡아내는 환경을 구축할 것
- 훅에서 차단할 때는 **에이전트가 이해할 수 있는 거부 사유**를 반환해 자가 수정 루프를 만들 것
- 같은 문제를 반복 수정하지 말고, 결과를 만든 **스킬/규칙 자체를 개선**하는 방향으로 접근 (예: "API 키는 항상 Secret Manager에서 로드" 규칙 추가)
- 차단 / 에이전트 자가 수정 / 사람에게 에스컬레이션 기준은 **에이전트의 해결 능력에 대한 확신**과 **사용 기간**(훅·스킬 성숙도)에 따라 결정
> ⚠️ 보안을 **shift-left**하며 초기부터 모든 것을 차단하면 **오탐(false positive)** 과 개발자 좌절을 유발하고 SDLC 전체가 느려질 수 있음 — 개발 단계는 유연성(작업 공유·리뷰 요청 등)이 필요함
- 보안 도구가 제대로 구성되지 않은 상태에서의 전면 차단은 특히 초기 단계에서 혼란을 키우므로 점진적으로 강화할 것
