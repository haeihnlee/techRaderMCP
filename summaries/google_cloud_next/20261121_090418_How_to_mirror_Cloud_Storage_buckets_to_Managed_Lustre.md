# How to mirror Cloud Storage buckets to Managed Lustre

- **컨퍼런스**: Google Cloud Next
- **출처**: https://www.youtube.com/watch?v=MpDi3iDZF4k
- **요약 일시**: 2026-11-21 09:04:18

---

## 🔑 핵심 요약
- **Managed Lustre Cloud Storage Mirror**는 GCS 버킷을 Managed Lustre 병렬 파일 시스템에 연결하는 **자동 단방향 동기화** 서비스
- 내부적으로 **Storage Transfer Service**가 버킷 이벤트(생성·업데이트·삭제)를 받아 Lustre에 반영하므로 수동 복사 스크립트가 필요 없음
- 대규모 AI 학습·HPC에서 **저렴한 GCS 데이터 레이크**와 **서브 밀리초 Lustre 계층**을 맞춰 두어 가속기가 노는 시간을 줄임

---

## 📣 주요 발표 내용
- GCS → Managed Lustre **이벤트 기반 실시간 동기화** 지원 (단방향)
- 작업이 읽기 전에 **데이터와 메타데이터를 미리 준비(pre-hydration)**
- 미러 생성 시 GCS 버킷 경로를 Lustre 루트 마운트 등 원하는 디렉터리에 매핑
- **삭제 파일 보존 플래그**: GCS에서 삭제된 파일(예: 체크포인트)도 Lustre에 남겨 둘 수 있음
- **삭제 파일 미보존 플래그**로 바꾸면 GCS 삭제가 Lustre에도 반영되어 공간을 확보함
- 미러 리소스를 삭제하면 동기화만 끊기고 **양쪽 저장소의 파일은 그대로 유지**

---

## 💡 개발자 포인트
- 설정 순서:
  1. Managed Lustre 인스턴스가 활성·정상 상태인지 확인
  2. **GCS 서비스 에이전트** 초기화 (Lustre가 버킷을 인증해 읽을 때 쓰는 백그라운드 ID라서 필수)
  3. 최소 권한 원칙에 따라 버킷·객체 권한만 담은 **커스텀 프로젝트 수준 IAM 역할** 생성
  4. 소스 버킷에서 이 역할을 Managed Lustre 서비스 계정에 바인딩
  5. 미러 생성: 생성이 오래 걸리므로 `--async` 로 백그라운드 실행
  6. 미러 목록 조회(list)와 상세 조회(describe)로 활성 상태 확인
- 클라이언트 VM(GCE)의 Lustre 마운트에서 초기 동기화 파일과 이후 업로드한 파일이 자동 반영되는 것을 확인함
- ML 학습 중 체크포인트·로그 디렉터리가 자주 바뀌는 경우 삭제 보존 정책을 워크로드에 맞게 정해야 함

> ⚠️ **이름 충돌 시 GCS가 우선**: 버킷이 업데이트되면 미러링된 디렉터리의 **로컬 수정이 덮어써짐**. 구조적 충돌은 건너뛰고 **Cloud Logging**에 기록됨

> ⚠️ 동기화는 **단방향(GCS → Lustre)** 이므로 학습 결과·로컬 체크포인트는 **미러링하지 않는 Lustre 디렉터리**에 저장할 것 (이 디렉터리는 영향을 받지 않음)
