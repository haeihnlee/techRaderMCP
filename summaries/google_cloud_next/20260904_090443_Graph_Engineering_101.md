## 🔑 핵심 요약
- **Graph Engineering**은 AI 에이전트 워크플로우를 그래프(노드 + 엣지) 구조로 설계하는 패턴으로, 실행 순서와 흐름을 제어하는 데 초점을 맞춤
- 노드에는 에이전트, 결정론적 함수, 라우터 등 다양한 역할이 가능하며, 노드 간에는 **공유 상태(shared state)**를 통해 정보가 전달됨
- Loop Engineering(단순 반복)·Agent Swarm(자율적 집단)과 구분되며, **워크플로우를 사전에 명확히 정의할 수 있는 복잡한 태스크**에 적합

---

## 📣 주요 발표 내용
- **Harness**: 모델 + 툴 + 메모리 + 가드레일을 포함하는 전체 실행 컨테이너
- **Loop**: 에이전트가 Harness 안에서 목표 달성까지 반복 실행하는 사이클
- **Graph**: 에이전트 노드와 함수 노드를 포함하는 조직도(organizational chart) 형태의 워크플로우
- 대표 패턴:
  - **Fan-out**: 5개 병렬 처리로 PR 정보를 동시에 수집
  - **Joiner**: 가장 느린 처리가 끝날 때까지 대기 후 결과 합산
  - **Router**: 조건에 따라 전문 에이전트(fixer) 또는 휴먼 승인 흐름으로 분기
- **Google Agent Development Kit (ADK)**를 사용해 멀티 에이전트 시스템 구축 가능

## 💡 개발자 포인트
- Graph Engineering vs. 유사 개념 혼동 주의:

> **Knowledge Graph** = 데이터 모델 중심 / **Graph Engineering** = 실행 행동(behavior) 및 순서 중심 — 이름이 비슷하지만 목적이 다름

- **Loop Engineering** 사용 시기: 단순·단일 목표 태스크 (예: 한 문단 요약)
- **Graph Engineering** 사용 시기: 복잡하고 단계가 명확히 정의된 태스크 (예: PR 자동 리뷰, 대형 문서 생성)
- **Agent Swarm** 사용 시기: 워크플로우를 사전에 정의하기 어려운 모호한 문제 — 각 에이전트에 개성(personality)만 부여하고 문제를 던짐

> Graph Engineering은 예측 가능성(predictability)·디버깅 용이성(debuggability)·제어성(control)이 높다는 것이 핵심 장점

- 본질적으로 **자료구조·알고리즘의 에이전트 시대 재해석** — fan-out/join/router는 기존 병렬·분기 패턴과 동일한 개념
