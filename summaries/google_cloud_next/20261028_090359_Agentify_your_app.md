# Agentify your app

- **출처**: https://www.youtube.com/watch?v=sYYNVN2ePLU
- **요약 일시**: 2026-10-28 09:03:59

---

## 🔑 핵심 요약
- **Build It** 시리즈 에피소드로, AI 개인 트레이너 앱의 핵심인 **에이전트 사양 문서**를 **Google Antigravity**와 Gemini의 대화형 Q&A로 설계하는 과정을 보여줌
- 시스템 지침은 **컨텍스트 캐싱**으로 서버에 캐시하고, 사용자 데이터는 **하이브리드 방식**으로 전달함 (일부는 클라이언트가 묶어서 보내고, 일부는 tool 호출로 실시간 조회)
- 요청 유형별 전용 엔드포인트 대신 **단일 통합 엔드포인트**를 두고, 에이전트가 **라우터 + 코치** 역할을 함께 맡아 **표준 출력 스키마**로 응답함

---

## 📣 주요 발표 내용
- 개발 흐름: **AI Studio**로 프로토타입 → **Google Antigravity**로 데이터·클라이언트 아키텍처 사양 작성 → 이번 회차에서 **에이전트 사양** 작성
- 최종 산출물인 에이전트 사양 문서의 구성
  - **마스터 시스템 지침**(캐시 컨텍스트): 페르소나, 동작 방식
  - **3계층 리빙 메모리 관리 프로토콜**
  - 의도 기반 **라우팅** 규칙
  - **출력 스키마 계약**과 응답 예시(few-shot)
  - 아키텍처 파이프라인 다이어그램, DB 접근 권한 정의
- 코치 페르소나: 기본은 "균형 잡힌 엘리트 코치"이고 사용자에 맞춰 스타일을 조정함. 답변은 간결하게 하되, 사용자가 더 물으면 자세히 설명함
- 운동 데이터: 컨텍스트 캐시에 운동 백과사전 전체를 넣을 수도 있지만, 사용자 중심 응답을 위해 **간결한 카탈로그 스키마**를 선택함
- 온보딩: 설정 마법사를 없애고 **동적 적응형 입력** 방식을 채택함. 질문 하나로 시작하고, 정보가 부족할 때만 추가로 질문함
- 응답은 **제안(proposal)** 형태로 나옴. 사용자가 검토하고 수락하거나, 계속 수정을 요청할 수 있음

## 💡 개발자 포인트
- LLM 요청은 **stateless**임. 매 요청에 캐시된 시스템 지침, 대화 기록, 추가 컨텍스트(선호도·운동 기록 등)를 함께 보내야 함
  - 클라이언트가 한 요청으로 묶어서 보내면 **빠름**
  - tool로 필요할 때 조회하면 **응답이 더 개인화됨**. tool 사용 시점은 에이전트가 판단함
  - 추천 방식은 **하이브리드**. 주간·일간 운동 계획 생성처럼 사용자가 기다릴 만한 요청에서는 tool 조회를 허용함
- **단일 통합 엔드포인트**를 선택한 이유
  - 사용자는 REST 엔드포인트를 신경 쓰지 않음. 버튼 입력(예: "월요일 업데이트")과 자유 채팅을 같은 경로로 처리함
  - 클라이언트가 어느 엔드포인트를 부를지 추측하면 모호한 요청이 잘못 전달됨
  - 컨텍스트가 많든 한 문장뿐이든 에이전트가 의도를 평가해 **결정론적 출력 스키마**로 응답하므로, 앱이 바로 렌더링할 수 있음
- **DB 쓰기 권한 최소화**
  - 운동 기록·운동 계획: 에이전트가 직접 쓸 수 없음. 사용자가 제안을 수락하면 서버가 에이전트를 거치지 않고 기록함
  - **리빙 메모리 프로필**: 에이전트가 직접 씀 (예: "달리기를 많이 함"). 메모리는 **추출 / 변형 / 무효화** 지시문으로 관리함
  - 운동 기록과 운동 백과사전은 **읽기 전용**
- 프롬프트 카탈로그는 실제 서버 엔드포인트와 정확히 맞아야 함

> ⚠️ **주의**: Gemini가 사양 작업 중에 정의된 적 없는 엔드포인트 목록을 **임의로 만들어 낸** 사례가 나옴. AI가 만든 사양은 기존 문서와 대조해 검증해야, 이후 서버 설계가 엉뚱한 방향으로 가는 것을 막을 수 있음

> ⚠️ **주의**: 생성된 사양에 대상 LLM 엔진이 옛 버전(**Gemini 2.0**)으로 잘못 적혀 있었음. 생성된 문서에 적힌 모델 버전은 직접 확인하고 고쳐야 함
