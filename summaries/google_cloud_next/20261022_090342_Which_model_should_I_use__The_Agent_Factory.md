## 🔑 핵심 요약
- "어떤 모델을 써야 하나?"에 대한 답은 **상황에 따라 다르다**이며, 가장 쉬운 방법은 에이전트의 **Auto 모드**(난이도에 따라 Flash-Lite / Flash / Gemini 4로 자동 라우팅)를 쓰는 것
- 정석은 **Evals(평가)**: 실제 유스케이스로 여러 모델을 테스트하고, **일관되게 정답을 내는 가장 저렴한 모델**을 고른다
- Evals를 돌리기 부담스럽다면 같은 프롬프트를 여러 모델에 보내는 **"미니 eval"**로 감을 잡을 수 있음. 실험 결과 **항상 가장 큰 모델이 필요한 것은 아님**

## 📣 주요 발표 내용
- **모델 선택 전략 3단계**
  - Auto 모드: 프롬프트 난이도를 판단해 적절한 모델로 자동 라우팅 (대부분의 경우 적절)
  - Evals: 정확도 수치(예: 98% / 95% / 100%)로 모델들을 비교한 뒤, 필요한 정확도 대비 비용이 가장 낮은 모델 선택
  - 미니 eval: 동일 프롬프트를 여러 모델에 보내 결과를 직접 비교하며 직관 쌓기
- **실험 1 — 텍스트 기반 음악 생성 (`Strudel`)**
  - WAV 같은 완성 파형은 일부만 고칠 수 없어 통째로 다시 생성해야 하므로, **코드(텍스트)로 음악을 표현**하는 방식 선택
  - Flash-Lite 결과가 가장 호평받음 → **승자: Gemini Flash-Lite**
  - Flash 결과는 마음에 들지 않는 부분(금속성 핑 소리)만 코드에서 지워 바로 개선
  - Gemini 4 결과는 코드 줄 수가 훨씬 많고 복잡해 **세밀한 조정 여지가 큼** → 영화 수준처럼 복잡한 요구에 적합
- **실험 2 — 영상 스크립트로 다이어그램 제안·생성 (`Mermaid`)**
  - 영상 트랜스크립트를 넣고, **어떤 다이어그램이 어디에 필요한지**까지 모델이 직접 판단해 생성하도록 지시 (`Antigravity`에서 실행)
  - Flash-Lite: 다이어그램 2개, 화살표 겹침 등 아쉬움 있으나 대체로 정확 (B~B+)
  - Flash: 다이어그램 3개, 더 깔끔하고 "도구 사용 여부" 다이어그램 추가 (A-)
  - Gemini 4: 다이어그램 3개, "질문 유형에 따라 도구 사용 여부를 판단하는" 흐름을 **하나의 통합 플로우**로 표현해 가장 의도에 부합 (A)

> 주의: 자동 생성 자막 기반이라 모델명 표기가 부정확할 수 있음 (예: "flashlight" → Flash-Lite, "argon"은 영상에서 Gemini 4 계열로 언급됨). 본문은 12,000자에서 잘려 결론 일부가 빠져 있음.

## 💡 개발자 포인트
- **비용 최적화**: 필요한 정확도 기준을 먼저 정하고, 기준을 만족하는 **가장 저렴한 모델**을 채택하는 것이 원칙
- 프로덕션 반복 작업이라면 **Evals 파이프라인**을 만들어 모델별 정확도를 수치로 비교할 것
- 출력물을 **텍스트 기반 포맷**(`Mermaid`, `Strudel` 코드 등)으로 받으면 사람이 직접 일부만 고칠 수 있어 **재프롬프트 횟수가 줄어든다** (예: 섭씨↔화씨 수정)
- 단순 작업은 Flash-Lite로도 충분히 좋은 결과가 나오고 **속도도 빠름** → 복잡도·깊이가 필요할 때만 Gemini 4로 올리기
- 대형 모델은 출력이 더 풍부하지만 **필요 이상으로 복잡**해질 수 있음 → 결과물의 복잡도가 요구사항에 맞는지도 평가 기준에 넣기
- 모델이 답을 이미 아는 질문("하늘은 왜 파란가")과 외부 정보가 필요한 질문("우비를 입어야 하나?" → 날씨 도구 호출)은 **harness의 도구 호출 설계**로 구분해야 함

## 📅 버전 / 출시 일정
| 모델 | 음악 생성 (`Strudel`) | 다이어그램 (`Mermaid`) | 특징 |
|------|----------------------|------------------------|------|
| Gemini Flash-Lite | 🏆 승자 | B ~ B+ (2개) | 가장 빠름, 단순 작업에 충분 |
| Gemini Flash | 일부 수정 후 개선 | A- (3개) | Flash-Lite보다 깔끔 |
| Gemini 4 | 복잡·정교, 조정 여지 큼 | A (3개, 통합 플로우) | 복잡한 요구사항에 적합 |
