## 🔑 핵심 요약
- Material·Cupertino 라이브러리가 핵심 프레임워크에서 **전용 패키지로 분리**되면서, Flutter 팀은 `widgets.dart`의 기본 위젯 계층을 **Raw 위젯**(예: `RawMenuAnchor`)으로 강화하고 있음
- 커뮤니티 패키지 **Mix**(스타일링 계층)와 **Remix**(동작·접근성 내장 컴포넌트)로 브랜드에 맞는 디자인 시스템을 처음부터 구축 가능
- **Widgetbook**으로 디자인 라이브러리를 카탈로그화·테스트하고, **Widgetbook Cloud**로 PR 단위 시각적·접근성 회귀 리뷰 가능 (에이전트 워크플로우와 연계)

---

## 📣 주요 발표 내용
- **Raw 위젯 확대**: 동작과 접근성은 모두 갖췄지만 스타일은 없는 위젯 ("프라이머만 바른 벽")
- Raw 위젯은 요청에 따라 계속 추가 중 → 필요한 위젯이 없으면 **이슈 제기 또는 직접 기여** 권장
- pub.dev의 대안 위젯 세트 소개: **Shadcn**, **Fluent UI**(Windows 스타일), **Yaru**(Ubuntu 스타일)
- **Mix**: 위젯 트리에 섞여 있던 스타일링을 **분리·재사용·조합 가능한 스타일 계층**으로 이동
  - 공유 스타일 변경 시 해당 스타일을 쓰는 모든 위젯에 반영
  - 컨텍스트 반응형 스타일: **다크 모드**별 색상, **호버** 시 그림자 등을 위젯 상태 관리 없이 스타일에 선언
  - 스타일에 **애니메이션**을 추가해 호버 전환·기울기 변화를 부드럽게 처리
- **Remix**: Mix + Flutter 기본 위젯 = 동작·접근성 내장 스타일 컴포넌트
  - 버튼의 컨테이너·라벨·아이콘을 하나의 Mix 스타일로 지정, 호버/프레스 피드백 정의
  - Remix 기반 예시 디자인 시스템 **Portal** 소개
- **Widgetbook**: 위젯 카탈로그를 대화형으로 탐색
  - 별도 Flutter 앱에서 메타 정보를 선언하고 `build_runner` 실행 → 생성자 기반 **타입 안전한 Story 클래스** 자동 생성
  - 생성자 매개변수는 폼 필드(args)로 제어 — 문자열·숫자·enum 변경 시 즉시 리빌드
  - **Modes**로 테마·로케일·텍스트 배율 등 조합(예: 64가지)의 테스트 매트릭스 구성
- **Widgetbook Cloud**: PR의 시각적 변경 자동 포착, 브라우저에서 빌드 확인, **접근성 회귀**(시맨틱 레이블 누락 등) 검토 후 승인 → CI 통과

## 💡 개발자 포인트
- 자체 디자인 시스템이 필요하다면 Material 커스터마이징보다 **Raw 위젯 + Mix/Remix**로 처음부터 만드는 편이 더 쉬울 수 있음
- Mix를 쓰면 `Theme.of(context).brightness` 체크나 호버 상태 `setState` 같은 **보일러플레이트가 스타일 선언으로 대체**됨
- Widgetbook 사용 시 앱 실행·내비게이션·로그인 없이 컴포넌트 단위로 즉시 확인 가능
- 테스트 매트릭스로 엣지 케이스를 조기 발견 — 예: **iPhone SE + 텍스트 배율 200%**에서 결제 요청 행 레이아웃 깨짐
- 같은 테스트 실행에서 **작은 탭 영역**, **누락된 시맨틱 레이블** 같은 접근성 위반도 검출
- 에이전트 워크플로우 연계
  - 에이전트가 Stories를 통해 컴포넌트를 이해하고 디자인 시스템을 일관되게 사용
  - 에이전트가 테스트 시나리오를 작성해 로컬에서 시각적 버그를 자동 수정
  - 테스트 매트릭스를 원본 **Figma** 디자인과 자동 대조 검증

> 주의: 시각적 diff만으로는 시맨틱 레이블 누락 같은 **접근성 회귀**를 잡을 수 없으므로, 리뷰 시 접근성 검사를 별도로 확인해야 함

> 에이전트가 코드를 빠르게 생성하면서 **리뷰가 병목**이 되고 있음 → PR 단위 시각적 리뷰 자동화 고려
