## 🔑 핵심 요약
- Flutter 데스크톱(macOS·Linux·Windows)에서 **여러 창을 렌더링**할 수 있는 **실험적 Windowing API** 공개
- **Canonical이 설계·구현을 주도**하고 Google이 설계·코드 리뷰를 지원 (2024년부터 협업)
- **5가지 윈도우 유형**(regular·dialog·popup·tooltip·satellite)을 크로스 플랫폼으로 지원하며, 모든 창이 **단일 위젯 트리**를 공유

> ⚠️ Windowing API는 **실험 단계(early preview)** 입니다. API 이름·시그니처는 향후 바뀔 수 있으니 프로덕션에 적용할 때 주의하세요.

---

## 📣 주요 발표 내용
- **윈도우 유형 5종** 도입 (Ubuntu 데스크톱 20년+ 경험을 바탕으로 선정)

| 유형 | 용도 | 특징 |
|---|---|---|
| **Regular** | 앱의 주요 콘텐츠 창 (예: 브라우저 탭 분리) | 제목 표시줄, 크기 조절·최대화·최소화·전체 화면 |
| **Dialog** | 사용자에게 작업 요청 | modal(부모 있음) / modeless(부모 없음), 응답해야 닫힘 |
| **Popup** | 우클릭 메뉴, 자동완성 등 | **anchor** 기준 위치 유지, 다른 창과 상호작용하면 닫힘 |
| **Tooltip** | 버튼 도움말 등 작은 정보 | popup과 비슷하지만 **입력 포커스를 받지 않음** |
| **Satellite** | 도구 상자 등 보조 창 (예: GIMP 팔레트) | 부모 창이 움직이거나 크기가 바뀌어도 상대 위치 유지 |

- 창은 **무한한 부모-자식 트리** 구성 가능 (regular → dialog → popup → popup …), 다만 **얕은 트리 권장**
- Linux 예제 앱이 macOS·Windows에서도 **똑같은 모양과 동작**으로 실행됨
- **Material 통합**: windowing을 켜면 기존 Material dialog가 데스크톱에서 **실제 별도 창**으로 뜨고, 모바일에서는 기존 단일 창 동작 유지
- Material **메뉴·툴팁**도 자체 창을 쓰도록 마이그레이션할 계획

## 💡 개발자 포인트
- 사용하려면 **`main` 채널로 전환**한 뒤 **windowing 기능 플래그를 활성화**해야 함 (`flutter channel main`)
- **윈도우 컨트롤러**: 플랫폼과 통신해 창을 생성·업데이트·파괴함
  - 초기 구성(크기, 제목 등)을 넘기지만 **플랫폼이 이 값을 그대로 적용하지 않을 수도 있음** (예: 화면이 작으면 창 크기를 줄임)
  - 유형마다 전용 컨트롤러가 있음 — 예: dialog는 **다이얼로그 윈도우 컨트롤러**를 쓰고, 생성자에서 **부모 컨트롤러를 선택적으로** 받음
  - 생성 후 제목·크기 변경, 창 파괴 가능

> ⚠️ 윈도우 컨트롤러는 **데스크톱 플랫폼에서만** 생성하세요. 모바일에서 생성하면 **예외가 발생**합니다.

- **윈도우 위젯**: 컨트롤러와 `child`를 넘겨 창에 콘텐츠를 렌더링함
- 모든 창이 **하나의 위젯 트리**에 있으므로 별도 작업 없이 **창 간 상태 공유**가 됨 → **Riverpod**, **Bloc** 같은 상태 관리 패키지를 그대로 쓸 수 있음
- **윈도우 델리게이트**: 닫기(X 클릭)·파괴 같은 **라이프사이클 이벤트**를 받음
  - 컨트롤러 생성자로 넘겨 등록
  - 예: 메인 창 destroy 이벤트에서 앱 전체 종료
- **`WindowScope`**(InheritedWidget): 창의 그리기 영역 크기, **포커스·최소화·최대화·전체 화면 상태**를 조회
- 대부분은 API를 직접 다루기보다 **디자인 시스템(Material 등)이 내부에서 처리**하는 방식으로 쓰게 될 예정
- 피드백은 **GitHub 이슈**로 받음
