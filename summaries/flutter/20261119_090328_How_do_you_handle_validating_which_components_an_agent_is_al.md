# How do you handle validating which components an agent is allowed to request?

- **컨퍼런스**: Flutter
- **출처**: https://www.youtube.com/watch?v=DyDK6QN-a9o
- **요약 일시**: 2026-11-19 09:03:28

---

## 🔑 핵심 요약
- 에이전트가 UI를 생성할 때 사용할 수 있는 컴포넌트는 **카탈로그(catalog)**에 노출된 것으로 **제한**됨
- 1.0 버전의 카탈로그는 컴포넌트별로 **허용된 부모 컴포넌트**와 **허용된 자식 컴포넌트**를 지정할 수 있음
- 덕분에 에이전트가 잘못된 계층 구조(예: 작은 버튼 안에 accordion 전체를 넣는 것)를 만드는 일을 막을 수 있음

---

## 📣 주요 발표 내용
- 시청자 질문(Muhammad): "에이전트가 새 UI를 만들 때 어떤 컴포넌트를 써도 되는지 어떻게 검증하나?"
- 답변: 에이전트는 1.0 기준 **카탈로그에 노출된 컴포넌트만** 사용할 수 있음
- 카탈로그 기능 강화: 각 컴포넌트에 **allowed parent components** 지정 가능
- 카탈로그 기능 강화: 각 컴포넌트에 **allowed children components** 지정 가능

---

## 💡 개발자 포인트
- 에이전트 기반 생성형 UI(Agent → UI)를 설계할 때는 **카탈로그를 화이트리스트처럼 사용**해 노출할 컴포넌트를 최소한으로 정의하는 것이 좋음
- 부모/자식 허용 규칙을 정의해 두면 **구조 검증을 카탈로그 단에서** 처리할 수 있어, 렌더링 단에서 따로 방어 코드를 둘 부담이 줄어듦
- 버튼·칩처럼 작은 leaf 컴포넌트에는 자식을 제한하고, 컨테이너 컴포넌트에는 허용할 자식 타입을 명시하는 식의 설계를 고려할 것

> 주의: 영상이 짧은 Q&A 클립이라 구체적인 API명이나 스키마 필드명은 나오지 않습니다. 실제 적용 전에는 공식 문서에서 카탈로그 정의 형식을 확인하세요.
