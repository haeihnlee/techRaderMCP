## 🔑 핵심 요약
- 폴더블 대응은 **브레이크포인트(너비·높이)만의 문제가 아니며**, 기기 **자세(posture)**·힌지 위치까지 고려해야 함
- 별도 패키지 없이 `MediaQuery`의 디스플레이 기능(display feature) 정보로 화면 분할 영역과 자세를 얻을 수 있음
- 실기기가 없어도 Android 에뮬레이터(폴더블 프로필)로 개발·테스트를 시작할 수 있음

## 📣 주요 발표 내용
- 일반 폰은 너비·높이와 XS/S/M/L **브레이크포인트**만 신경 쓰면 됐지만, 폴더블은 추가 정보를 제공함
- 폴더블이 주는 정보: 펼침 각도, 완전히 펼침/반쯤 열림, 가로/세로 접힘 방향
- **펼침 각도 값 자체는 거의 쓰이지 않음** — 90°인지 95°인지보다 "반쯤 열림 vs 완전히 펼침" 같은 **자세** 정보가 실제로 중요
- `MediaQuery`가 현재 자세 정보를 제공하며, display feature 목록이 사용할 수 있는 정보 중 가장 큰 범위
- 얻을 수 있는 자세: 책(book), 탁상형(tabletop), 완전히 펼침, 완전히 닫힘 — 방향(orientation)과 조합해 활용
- 과거 Microsoft 등이 만든 듀얼 스크린 패키지는 분할된 화면 크기를 제공했지만, 지금은 `MediaQuery`에 같은 기능이 있어 **별도 패키지 없이도 가능**
- 접힌 상태·주머니 속 상태는 일반 폰처럼 다루면 되므로 따로 처리할 것이 거의 없음

## 💡 개발자 포인트
- 펼쳤을 때 브레이크포인트가 바뀌므로 **전체 화면 레이아웃(태블릿 레이아웃에 가까운 형태)**을 따로 준비할 것
- 넓은 화면에서 화면 전체를 가로지르는 큰 하단 내비게이션 바는 보기 좋지 않음 → 내비게이션 레일 등으로 **내비게이션 구조 전환** 고려
- 힌지 기준으로 UI를 나눌 때(한쪽엔 콘텐츠, 다른 쪽엔 컨트롤 등) `MediaQuery`의 display feature 영역(bounds)을 기준으로 좌/우 또는 상/하 슬롯을 구성
- 폴더블 하드웨어는 다양함: **물리적 힌지가 있는 기기**와 **유연하게 접히는(힌지 영역이 없는) 기기**를 모두 고려
- 실기기 없이 시작하려면 Android 에뮬레이터의 폴더블 프로필 활용 (iOS는 시뮬레이터로 폴더블 테스트 불가)
- Samsung Flip 같은 작은 커버 화면 기기는 발표자도 검증하지 못한 영역 → 지원할 계획이면 실기기 테스트 필요

> ⚠️ 주의: 발표에서는 **Android 17부터** 앱을 전체 화면에 맞게 최적화하는 것이 훨씬 중요해진다고 언급 — 폴더블·대화면에서 레이아웃이 단순히 늘어나기만 하지 않는지 미리 점검할 것
