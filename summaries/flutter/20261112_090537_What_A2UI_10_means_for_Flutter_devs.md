# What A2UI 1.0 means for Flutter devs

- **컨퍼런스**: Flutter
- **출처**: https://www.youtube.com/watch?v=w53eHYJ-n0I
- **요약 일시**: 2026-11-12 09:05:37

---

## 🔑 핵심 요약
- 에이전트가 텍스트 대신 앱 UI를 직접 생성하는 생성형 UI 프로토콜 **A2UI 1.0**이 출시됨
- Flutter 패키지 이름이 **Flutter GenUI → GenUI → A2UI Flutter** 순서로 바뀜. 0.x에서 1.0으로 넘어오면서 구성 요소 일부가 제거·통합·수정됨
- 1.0의 4대 변경점: **allowed parents/children 가드레일**, **Express 추론 형식**(추론 시간 약 50% 단축), **서피스당 여러 카탈로그 지원**, **Call Agent Function**, **확장 메타데이터**

---

## 📣 주요 발표 내용
- **허용된 부모/자식 (`allowed parents` / `allowed children`)**
  - 카탈로그 항목의 스키마에 컴포넌트 이름 목록을 넘겨 중첩 규칙을 정의함
  - 이 규칙은 두 겹으로 적용됨. ① 에이전트 프롬프트 스키마로 컴파일되어 LLM이 미리 알고, ② 위젯을 만들기 전에 클라이언트에서 강제됨
  - LLM이 잘못된 계층을 반환해도 앱이 죽거나 UI가 깨지지 않음. 패키지가 카탈로그 스키마로 검증한 뒤 에이전트에게 "렌더링 불가"라고 응답함
  - 예: 에이전트가 버튼 안에 주문 데이터 테이블을 통째로 넣는 식의 이상 동작을 막을 수 있음 (0.9에서는 막을 수단이 없었음)
- **Express 추론 형식**
  - 전송 데이터가 훨씬 간결해져 에이전트 응답 속도가 빨라짐
  - Solid Software의 헬스케어 데모 **GenUI Clinic**: 화면 전체 생성 시간이 약 10초에서 **5초**로 줄어듦
- **멀티 카탈로그 서피스**
  - 지금까지는 서피스 하나가 카탈로그 하나에 묶여 있었음. 이제는 여러 카탈로그를 동시에 지원함
  - 새 **메시지 프로세서** 클래스(기존 `Surface Controller`와 `Conversation`의 역할을 넘겨받음)에 여러 카탈로그를 등록할 수 있음
  - 등록된 카탈로그 전체에서 컴포넌트 이름이 자동으로 해석됨
- **Call Agent Function**
  - 렌더링된 컴포넌트가 에이전트의 함수를 직접 호출하고, 응답이 컴포넌트 자체 데이터로 바로 들어감
  - 새 턴이나 모델 루프 없이 같은 뷰 안에서 다시 그려짐. 생성된 UI가 "그림"에서 "도구"로 바뀜
  - Somnio Software의 암호화폐 투자 컴패니언 데모: 주문 초안에서 금액을 바꾸면 백엔드가 비중·수수료·남은 현금을 다시 계산함
  - 이 데모는 **Apache 2.0**으로 GitHub에 공개됨. Flutter 단일 코드베이스(iOS/Android/웹)이고, 백엔드는 Cloud Run + Gemini, 핀테크 UI 컴포넌트 6종과 스키마가 들어 있음. 데이터는 시뮬레이션이라 API 키가 필요 없음
- **확장 메타데이터**
  - 서피스, 개별 컴포넌트, 카탈로그 정의, 액션에 구조화된 데이터를 붙일 수 있음
  - 용도: 커스텀 라우팅 플래그, 스타일 정보, 메트릭·관측성 등
  - 에이전트/클라이언트 SDK가 직렬화, 전송, 파싱을 맡음

## 💡 개발자 포인트
> ⚠️ **Breaking Change**: 0.x에서 1.0으로 오면서 Gen UI의 6가지 구성 요소 중 일부가 제거·통합·크게 수정됨. 특히 `Surface Controller`와 `Conversation`의 역할은 새 메시지 프로세서 클래스로 옮겨짐. 기존 GenUI 코드는 마이그레이션해야 함
- 생성형 UI의 핵심은 **가드레일 설계**임. 자유도가 너무 낮으면 에이전트가 상황에 맞추지 못하고, 너무 높으면 지나치게 창의적으로 움직임. `allowed parents`/`allowed children`으로 범위를 조절할 것
- 카탈로그를 나눠 **모듈화**할 수 있음. 코어 UI 팀은 기본 디자인 시스템을 맡고, 도메인 팀(재무, 프로필 등)은 특화 카탈로그를 따로 게시하면 됨
- **모든 탭을 모델에 보내지 말 것**. 질문에 해당하는 상호작용(예: 바 탭, 칩)만 새 에이전트 턴을 시작하게 하고, 답이 정해진 값 변경은 `Call Agent Function`으로 백엔드에서 다시 계산할 것
> 핀테크 규칙: **모델은 산술 연산을 하지 않음**. 모든 숫자는 결정론적 백엔드 도구에서 나오고, LLM(Gemini)은 도구와 컴포넌트를 고르기만 함
- 헬스케어 사례: AI는 **위젯 선택만** 하고 데이터를 수정할 권한은 없음. 그래서 표시되는 데이터가 안전하고 예측 가능함
- 생성형 UI가 늘 정답은 아님. Somnio는 핀테크 유스케이스 8개를 테스트해 5개만 남겼고, 나머지(리스크 프로파일링, 비용 분류 등)는 **잘 설계된 폼이 더 나았음**
- 메타데이터 활용 예: 서피스를 만들 때 에이전트가 추적 토큰을 생성해 메시지에 넣음 → 모바일 앱이 `create surface` 메시지를 받으면 서피스 모델의 `metadata` 속성에서 토큰을 읽음 → 백엔드 로그(멀티 에이전트 Python)와 프론트엔드 로그를 연결할 수 있음
- 메타데이터를 넣는 방법: 결정론적 코드로 메시지를 만들면 파라미터에 넣으면 됨. 모델 응답을 쓰면 모델에게 메타데이터를 넣으라고 지시하거나, 결과 메시지를 후처리함
- 시작점: **a2ui.org** 퀵스타트, Flutter 데모 저장소의 `Comme Il`(케이터링 관리) 데모

## 📅 버전 / 출시 일정
| 항목 | 내용 |
|---|---|
| A2UI | 1.0 정식 출시 (영상 공개일 기준) |
| 이전 버전 | 0.9 (부모/자식 가드레일 없음) |
