# Buzz: One workspace for both people and AI agents

- **컨퍼런스**: Flutter
- **출처**: https://www.youtube.com/watch?v=QhYZEid79VU
- **요약 일시**: 2026-10-30 09:03:36

---

## 🔑 핵심 요약
- **Buzz**는 사람과 AI 에이전트가 같은 채널에서 함께 일하는 **메시징 플랫폼**이며, 모바일 앱을 **Flutter**로 개발함
- 출시 반응이 기대치의 **10~100배**를 넘었고, GitHub 다운로드 약 **50만 회**, 별 약 **3.3만 개**를 기록함
- 요청과 버그 수정이 몰리는 상황에서 Flutter의 빠른 개발 속도, 신뢰할 수 있는 테스트 피드백 루프, **핫 리로드**가 부담을 크게 줄여 줌

---

## 📣 주요 발표 내용
- 각자 에이전트와 따로 일하면 협업이 어려워지는 문제를, 에이전트의 생각·작업·선택 이유를 **투명하게 공유**하는 방식으로 해결함
- 에이전트 결과가 기대와 다르면 동료를 해당 채널로 불러 함께 디버깅하고 도구 사용법을 익힐 수 있음
- 엔지니어와 디자이너가 **코드 안에서 함께 작업**할 수 있음 (에이전트 코딩에서는 그동안 잘 되지 않던 부분)
- 코드를 다루지 않던 모바일 디자이너가 이제 Buzz 안에서 Flutter 코드를 직접 푸시함
- Buzz 안에서 시뮬레이터를 실행해 결과를 바로 확인할 수 있음
- 개발 중: **원격 에이전트 / 원격 작업 공간**, 앞으로 **음성 기능**도 붙여 모바일을 Buzz의 유일한 인터페이스로 만드는 것이 목표

---

## 💡 개발자 포인트
- 아키텍처를 **일부러 가볍게** 유지함. 과한 설계를 피하고, 패키지 생태계에 맡겨 기능 개발에 집중함
- 주로 쓰는 패키지:
  - `riverpod`: 상태 관리
  - `flutter_hooks`: 위젯 로직 재사용
  - `gpt_markdown`: 메시지의 마크다운 렌더링
  - Nostr 관련 패키지: Buzz 릴레이와의 통신 (핵심 기능)
- 빠르고 신뢰할 수 있는 테스트 피드백 루프 덕분에 **에이전트도 문제를 더 빨리 해결**함. 에이전트 코딩 환경에서 Flutter의 강점
- 가장 어려운 디자인 과제는 **에이전트 활동을 어떻게 보여 줄지**. 정적인 디자인을 넘겨받는 대신 핫 리로드로 실제 경험을 시뮬레이션하며 반복 개선함

> 디자이너가 직접 코드를 푸시하는 흐름이라면, 리뷰·테스트 자동화로 품질 기준을 지키는 장치가 필요함
