## 🔑 핵심 요약
- **AI 코딩 에이전트의 Skill**은 반복 작업이나 한 번뿐이어도 자동화하고 싶은 복잡한 워크플로를 재사용 가능한 지침으로 만드는 방법이다.
- Flutter 프로젝트에서는 코드 리뷰, 신규 기능·엔드포인트 추가, 레이아웃 설계, 실제 화면 캡처 기반 QA를 Skill로 표준화할 수 있다.
- Skill은 단순한 Markdown 파일이라도 `prompt injection`을 포함할 수 있으므로 공식 저장소와 패키지 관리자의 Skill을 우선 사용하고 내용을 검토해야 한다.

## 📣 주요 발표 내용
- **Skill의 역할**
  - `prompt`는 현재 작업에 대한 일회성 지시다.
  - `rules`는 에이전트가 항상 읽어야 하는 프로젝트 규칙이다.
  - `skills`는 특정 작업이 필요할 때만 로드하는 선택적 지침·스크립트·참조 자료다.
- **Skill을 만들어야 하는 신호**
  - 코드 리뷰처럼 동일한 단계를 반복해서 수행할 때 유용하다.
  - Flutter 앱에 모바일 광고를 추가하는 것처럼 한 번 수행하더라도 큰 워크플로를 자동화하고 싶을 때 사용할 수 있다.
- **추천하는 Flutter용 AI Skill 5가지**
  1. Skill 자체를 생성하는 `skill creator` Skill
  2. 독립적인 에이전트가 검토하도록 구성하는 `code review` Skill
  3. 프로젝트의 디자인 시스템·데이터 소스·내비게이션 규칙을 반영한 신규 기능 추가 Skill
  4. `Row`, `Column`, `Wrap`, `Stack`, `Flexible`, `Expanded` 사용법을 안내하는 기본 레이아웃 Skill
  5. 앱을 실행하고 실제 화면을 캡처해 시각적 QA를 수행하는 스크린샷 Skill
- `code review`와 PR 트리아지를 서로 다른 에이전트에 맡기고 결과를 교차 검증하면 리뷰 품질을 높일 수 있다.
- 실제 스크린샷이나 애니메이션 `WebP`를 활용한 QA는 코드·테스트 결과만으로 놓칠 수 있는 UI 결함을 발견하는 데 효과적이다.

## 💡 개발자 포인트
- Skill 설명에는 `use when adding new feature to our app`처럼 언제 적용할지 명시해야 에이전트가 적절한 시점에 Skill을 로드한다.
- `skill creator`가 생성한 파일도 그대로 신뢰하지 말고 질문·참조·스크립트·에셋을 직접 검토하고 프로젝트에 맞게 수정해야 한다.

> 인터넷에서 내려받은 `.md` 파일도 안전하지 않을 수 있다. 숨겨진 유니코드나 `prompt injection`이 API 키 탈취 등 위험한 동작을 유도할 수 있으므로 공식 Flutter·Dart 저장소나 신뢰할 수 있는 패키지 관리자의 Skill을 사용한다.

- 에이전트는 결과를 빠르게 내기 위해 불필요한 `Container`와 고정 위치를 조합할 수 있으므로 반응형 UI에서는 레이아웃 Skill로 적절한 위젯 선택을 유도한다.
- `golden test`는 폰트와 이미지 로딩 차이를 관리해야 하지만 UI 회귀 검출에 유용하며, 실제 스크린샷 기반 검증은 전체 동작과 제스처를 확인하는 QA에 적합하다.
- AI가 코드의 품질은 평가해도 해당 코드가 제품에 정말 필요한지는 판단하지 못할 수 있으므로, 도메인 맥락과 인간의 최종 검토를 유지해야 한다.
- 여러 에이전트와 병렬 작업을 사용할수록 프로젝트 규칙·Skill·검증 절차를 명확히 해 결과를 통합해야 한다.
